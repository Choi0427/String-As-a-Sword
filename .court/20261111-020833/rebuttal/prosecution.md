# Rebuttal: Prosecution

1. **Survives only against the weakest rival.** Yes, Inspector tuning leaves both gaps open. But a visual editor or a Notion or spreadsheet import also gives drawn shapes and note-keyed attacks, so this point does not show that the text format is the efficient choice. "New shapes need no code" is also overstated, because anchors, responses and the parser all have to be written in C# first.

2. **Weakened.** The fairness checks were built for "a fixed C# enum of 9 kinds", and the record does not say they work on arbitrary drawn masks. Today a rejected attack is "deferred or skipped", which wrecks a fixed timeline that is supposed to land on the song. The validator, the parser and the new balance targets are all new work. Calling re-measuring "a single command" is a claim the defense makes without evidence.

3. **Unproven for this user.** Text suits Claude Code, but the question is whether it is efficient for *the designer* who wants to design "by hand". The defense itself concedes that the record does not say whether the user is comfortable editing text. The user already designs in Notion. Hand-typed 8×8 grids with anchors give no preview against the music.

4. **Survives, but it is beside the point.** The format can hold section pools, but "more cases to validate" means the hardest balance work is still undecided.

**Deciding point:** Point 2. The method's efficiency rests on the claim that the existing safety net is "reused, not new". The record does not show that this code handles hand-drawn shapes or authored timings. If it does not, the cheap path turns into a rewrite.
