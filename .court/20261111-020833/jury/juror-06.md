VOTE: NOT GUILTY
REASON: As a builder, I see a text file plus a parser plus a menu command that wraps the fairness checks and bot runs the project already has as the cheapest thing that can actually be built and diffed, and every rival (GUI, Notion import, spreadsheet) needs that same data model, parser and validator underneath, with more work on top.
DECIDING FACT: The code already checks fairness before publishing an attack (dodge route within the warning via DodgeActions, no invalidating of shown safe cells, no gap shorter than one beat), and seeded bot simulation already runs thousands of games, so the validator reuses checks that exist instead of inventing them; the "deferred or skipped" runtime fallback just has to be reported as an authoring error instead.
WOULD FLIP IF: The record showed that those fairness checks only work on the 9 hard-coded enum shapes and cannot be run on an arbitrary 8x8 cell mask at an authored note, because then "reuse the existing fairness code" becomes a rewrite and the cheap path stops being cheap.
