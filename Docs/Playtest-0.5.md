# 0.5v 플레이테스트 계획

2026-11-14 작성. 대상 빌드는 battle-8(RCM 채보 321노트, 보스 HP 35/8/14/54, 보스 채보 3단계 80공격)에 아트 1차 적용(나이트 모델, 판정선, 노트 4종, 공격 장판 2종)을 더한 것이다. 이 빌드를 0.5v로 부른다.

지금까지의 수치는 모두 봇 시뮬레이션이다. 사람이 플레이한 기록은 없다. 이 테스트의 목적은 시뮬레이션이 답하지 못한 질문에 사람 데이터로 답하고, 미뤄 둔 결정(플레이어 HP, 예고 길이, 보스 HP)을 내리는 것이다.

## 1. 시뮬레이션이 말해 준 것과 못 말해 준 것

| 항목 | 시뮬레이션 기록 (battle-8, 1,800판) | 사람에게서 확인할 것 |
| --- | --- | --- |
| 클리어율 | 누락 없음 99.8%, 5% 누락 95.8% | 봇은 노트 정각에 반응하고 예고를 항상 읽는다. 사람의 실제 클리어율 |
| 사망 | 0판. 스테이지의 `playerMaxHp`가 300이라 측정되지 않음 | HP 5에서 몇 번 맞고 어디서 죽는가 |
| 5% 누락 사망률 | battle-6에서 13.1% (HP 5) | 사람의 입력 누락률이 0%와 5% 중 어디에 가까운가 |
| 예고 길이 | 대부분 1노트(0.69초). 봇에게는 충분 | 1노트 예고를 보고 피하거나 막을 수 있는가 |
| 넓은 모양 | 아마존·외길(4노트), 이중고리(2노트) 통과 | 모양을 읽고 안전한 칸을 찾는가 |
| 무력화 후 여유 | 중앙값 48노트(약 33초), 상한 50에 근접 | 이 구간이 길거나 지루한가. 싸비3 패턴을 보는 사람이 있는가 |
| 행동 비율 | 공격 43.9 / 이동 45.2 / 방어 10.8 | 사람의 실제 비율. 방어를 쓰기는 하는가 |
| 필수 대응 | 방어 필수 P10 8회, 회피 필수 P10 21회 | 회피 필수가 과하게 느껴지는가 |
| 빠른 구간 | 한 박보다 짧은 간격에서는 공격을 내지 않음 | "리듬에만 집중하는 구간"으로 받아들여지는가 |

이번 버전에서 화면이 바뀌어 시뮬레이션으로는 알 수 없는 항목도 있다.

- 장판 2종: 일반(흰색 + 테두리 글로우)과 강화(더 투명 + 빗금)를 구분하는가.
- 보드 전체 공격은 일반 장판으로 보이지만 가드해야 막힌다. 설명 없이 이를 알아내는가.
- 16칸이 넘는 공격은 숫자 배지를 2×2 묶음당 하나만 보여 준다. 남은 노트 수를 읽는 데 지장이 없는가.
- 노트 4종(기본, 2연, 3연, 홀드)과 판정선 글로우로 칠 타이밍을 읽는가.

## 2. 테스트 전에 끝낼 일

| 순서 | 할 일 | 이유 |
| --- | --- | --- |
| 1 | `FourPhasePrototype.asset`의 `playerMaxHp`를 300에서 5로 되돌린다 | 300이면 사망이 없어 HP에 대한 데이터를 얻지 못한다. 세션 B(3절)에서만 300을 쓴다 |
| 2 | Windows 빌드를 새로 만든다 | 문서에 남은 마지막 빌드 기록은 battle-3(10월 23일)이다 |
| 3 | 빌드에서 전체 흐름을 한 번 끝까지 돈다 | 메인화면 → 스토리 → 전투 → 엔딩 → 흰 메인화면. 아트 적용 후 빌드에서는 확인하지 않았다 |
| 4 | 3연 노트 빔과 강화 장판을 눈으로 확인한다 | 에디터 캡처로 확인하지 못한 두 가지다 |
| 5 | 판마다 결과를 남길 방법을 정한다 | 전투 로그가 빌드에서 파일로 남는지 확인하고, 남지 않으면 화면 녹화로 센다 |
| 6 | 테스트 PC에서 입력 싱크·화면 싱크 값을 맞춘다 | 싱크가 틀리면 모든 판정 데이터가 오염된다 |

1번은 밸런스 값 변경이다. 진행 전에 결정이 필요하다.

## 3. 참가자와 세션 구성

- 인원: 6~8명. 팀원이 아닌 사람으로 구한다.
- 구성: 리듬게임 경험자와 비경험자를 절반씩. 사전 설문으로 나눈다.
- 한 사람당 약 30분. 한 판은 약 4분이다.

| 단계 | 시간 | 내용 |
| --- | --- | --- |
| 사전 설문 | 2분 | 리듬게임 경험, 체스 규칙을 아는지 |
| 싱크 확인 | 2분 | 설정 화면에서 입력 싱크를 참가자에게 맞춘다 |
| 1회차 (세션 A) | 5분 | 조작 키(WASD 이동, J 공격, K 방어)만 알려 주고 규칙은 설명하지 않는다. 생각을 소리 내어 말하게 한다. HP 5 |
| 중간 질문 | 3분 | 4절의 이해도 질문 |
| 2~3회차 (세션 A) | 10분 | 물어보면 규칙을 답해 준다. HP 5 |
| 4회차 (세션 B) | 5분 | 한 번도 클리어하지 못한 참가자만. HP 300으로 끝까지 보게 한다 |
| 사후 설문 | 5분 | 5절 |

세션 B는 죽어서 후반부를 못 본 참가자에게 2·3단계 패턴과 엔딩을 보여 주기 위한 것이다. 세션 B의 결과는 클리어율에 넣지 않는다.

## 4. 판마다 기록할 것

진행자가 관찰하거나 로그·녹화에서 센다.

| 항목 | 용도 |
| --- | --- |
| 결과: 클리어 / 사망 / 시간 초과 | 클리어율 |
| 사망한 노트 번호와 그때의 공격 이름 | 어려운 모양 찾기 |
| 피격 횟수, 가드 깨짐 횟수 | 플레이어 HP 결정 |
| Miss 수 ÷ 판정된 노트 수 | 사람의 누락률. 시뮬레이션의 0% / 5% 열 중 어느 쪽을 볼지 정한다 |
| 공격·이동·방어 횟수 | 행동 비율 비교 |
| 무력화된 노트 번호 | 여유 구간 길이, 싸비3 도달 여부 |
| 맞은 공격의 예고 길이(1노트 / 2노트 이상) | 예고 길이 결정 |

1회차 뒤 이해도 질문(답을 유도하지 않는다):

1. 흰 장판은 무엇이었나? 빗금이 있는 장판은 무엇이 달랐나?
2. 보드 전체가 하얘졌을 때 어떻게 해야 했나?
3. 장판 위 숫자는 무엇을 뜻하나?
4. 보스에게 피해를 주려면 어떻게 해야 하나?
5. 노트가 여러 모양이었는데 차이를 알았나?

## 5. 사후 설문

1~5점 척도:

- 난이도 (1 너무 쉬움, 3 적당, 5 너무 어려움)
- 공격 예고를 보고 대응할 시간이 충분했다
- 일반 장판과 강화 장판을 구분할 수 있었다
- 노트를 칠 타이밍을 알 수 있었다
- 보스가 멈춘 뒤 곡이 끝날 때까지의 구간이 지루했다
- 다시 하고 싶다

주관식:

- 가장 억울하게 맞은 순간은?
- 가장 재미있었던 순간은?
- 화면에서 어디를 주로 봤나? (노트 / 체스판 / 둘 다)
- 이해가 안 된 것은?

## 6. 판단 기준

아래 기준은 이 계획에서 제안하는 값이다. 팀이 확정한 수치가 아니므로 테스트 전에 합의한다.

| 질문 | 통과 기준 | 미달이면 |
| --- | --- | --- |
| 클리어율 | 3회차 안에 참가자의 60% 이상이 한 번 클리어 | 사망이 원인이면 HP, 시간 초과가 원인이면 보스 HP를 조정한다 |
| 플레이어 HP | 클리어한 판의 피격 중앙값이 2~4회 | 0~1회면 HP를 낮추거나 유지, 5회 이상으로 죽으면 HP 7을 검토한다(battle-4에서 40시드 참고값 83.3%) |
| 1노트 예고 | 1노트 예고 공격의 피격률이 2노트 이상 예고 공격의 2배 이하 | 1단계 기본 모양만 1노트로 두고 나머지를 2노트로 늘린다 |
| 넓은 모양 | 아마존·외길·이중고리에서 같은 참가자가 3회차에도 맞는 비율이 절반 이하 | 해당 모양의 예고를 늘리거나 모양을 단순화한다 |
| 장판 구분 | 이해도 질문 1·2에 참가자의 70% 이상이 1회차 뒤 바르게 답함 | 강화 장판 대비를 높이거나 첫 등장 때 안내를 넣는다 |
| 무력화 후 구간 | "지루했다" 평균 3점 이하 | 보스 HP를 올리거나 HP 하한을 둔다([LyricBossDesign.md](LyricBossDesign.md) 6절의 결정) |
| 누락률 | 측정값을 기록만 한다 | 5%보다 높으면 다음 시뮬레이션에 그 값의 누락 그룹을 추가한다 |
| 규칙 이해 | 1회차 안에 "잡음 수집 → 공격"을 스스로 해낸 참가자가 절반 이상 | 튜토리얼 또는 첫 판 안내가 필요하다(GDD v0.7 미결정 항목) |

## 7. 결과 정리

- 판별 기록은 표 하나로 모은다(참가자, 회차, 4절 항목).
- 결과 문서 `Docs/Playtest-0.5-Results.md`에 6절 표를 그대로 옮겨 실제 값과 판정을 채운다.
- 수치를 바꾸면 `combatVersion`을 올리고 [ChartBalance.md](ChartBalance.md)에 시뮬레이션을 다시 돌린 결과를 덧붙인다.

## 8. 이번 테스트에서 다루지 않는 것

- 홀드 반사(미구현).
- 킹 3D 모델과 VFX(아트 미도착).
- WASD와 마우스 이동 비교. 이번에는 WASD만 쓴다.
- 스토리 문구와 엔딩 연출의 평가. 끝까지 동작하는지만 본다.
