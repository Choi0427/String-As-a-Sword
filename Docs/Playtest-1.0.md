# 1.0v 플레이테스트 설문 (Softcon 제출용)

2026-11-27 작성. 대상 빌드는 battle-11(밸런스 목표 v2, [BalanceTargets.md](BalanceTargets.md))에 프롤로그, 튜토리얼, 난이도 쉬움·어려움, 엔딩까지 들어간 현재 `main`이다. 이 빌드를 1.0v로 부른다. 이전 계획은 [Playtest-0.5.md](Playtest-0.5.md)에 있다.

## 0. 이 테스트로 답할 질문

포스터의 '남은 것'에 있는 "사람 대상 플레이테스트"를 지우고, 그 자리에 사람 데이터를 넣기 위한 테스트다. 질문은 세 가지다.

| # | 질문 | 왜 중요한가 | 어디서 답을 얻나 |
| --- | --- | --- | --- |
| A | **"제약은 곧 서사"가 실제로 느껴지는가.** 플레이 중에 쌓인 답답함이 엔딩에서 해방감으로 바뀌는가 | 포스터의 디자인 명제. 지금은 주장일 뿐 측정한 적이 없다 | 5절 A·B·C, 감정 곡선 |
| B | **봇의 실력 가정이 맞는가.** 사람의 클리어율, 판정 오차, 누락률이 봇 프리셋과 얼마나 다른가 | 봇 클리어율(어려움 중수 81%, 쉬움 초보 77%)은 가정값 위의 숫자다([BalanceTargets.md](BalanceTargets.md) "아직 가정인 것") | 판정 로그(3절), 진행자 기록 |
| C | **곡을 몰라도 규칙에서 메시지가 읽히는가** | "곡을 배경음악이 아니라 규칙으로 옮긴다"는 목표가 통했는지 보는 질문 | 5절 D (의도를 알려 주기 전에 묻는다) |

질문 A의 "답답함"은 두 종류로 나눠서 묻는다. **의도된 답답함**("묶여 있다"는 느낌)과 **부당한 답답함**("판정이 이상하다", "억울하다")이다. 앞의 것은 높아야 하고 뒤의 것은 낮아야 한다. 이 둘을 구분하지 않으면 "답답했다"는 응답이 설계가 성공했다는 뜻인지 실패했다는 뜻인지 알 수 없다.

## 1. 참가자와 진행

- 인원: **최소 12명, 목표 20명.** 팀원이 아닌 사람으로 구한다. 포스터에 퍼센트를 쓰려면 10명은 넘어야 한다.
- 구성: 사전 설문(2절)으로 리듬게임 경험자와 비경험자를 나눈다. 가능하면 절반씩 모은다.
- 난이도 배정은 봇 비교를 위해 미리 정한다.
  - 리듬게임 경험자 → **어려움** (봇 '중수' 기준과 비교)
  - 비경험자 → **쉬움** (봇 '초보' 기준과 비교)
- 한 사람당 약 30분. 한 판은 약 4분이다.

| 단계 | 시간 | 내용 |
| --- | --- | --- |
| 동의·사전 설문 | 3분 | 2절. 녹화 동의를 받는다 |
| 싱크 맞추기 | 2분 | 설정 화면에서 입력 싱크를 참가자에게 맞춘다 |
| 1회차 | 8분 | 메인화면 → 프롤로그 → 튜토리얼 → 곡. **건너뛰지 않는다.** 규칙은 설명하지 않고, 생각을 소리 내어 말하게 한다 |
| 즉시 질문 | 1분 | 4절. 기억이 사라지기 전에 바로 묻는다 |
| 2~3회차 | 10분 | 프롤로그·튜토리얼은 Esc로 건너뛴다. 물어보면 규칙을 답해 준다 |
| 엔딩 보장 회차 | (필요할 때만) 5분 | 한 번도 클리어하지 못한 참가자만. 설정의 개발자 무적을 켜고 엔딩까지 보게 한다. **이 판은 클리어율에 넣지 않고**, 5절 C의 엔딩 문항에 '무적으로 봄' 표시를 한다 |
| 사후 설문 | 7분 | 5절 |

사후 설문 5절 D(메시지 해석)를 답하기 전에는 **곡 제목, 곡의 의미, 팀의 의도를 말하지 않는다.** 메인화면 하단의 "Inspired by 이승윤 <검을 현>"은 가리지 않아도 된다. 다만 곡을 아는지 여부는 2절에서 따로 묻는다.

## 2. 사전 설문

참가자 번호(P01, P02, …)를 먼저 적는다. 번호는 판정 로그 파일과 묶을 때 쓰고, 이름은 받지 않는다.

1. 리듬게임을 얼마나 해 봤나요? (단일 선택)
   - 거의 안 해 봤다 / 가끔 한다(한 달에 몇 번) / 자주 한다(주 1회 이상) / 고난도 곡을 클리어할 정도로 한다
2. 체스 규칙을 아나요? (단일 선택)
   - 모른다 / 말 움직임 정도는 안다 / 게임을 둘 수 있다
3. 이승윤의 「검을 현」을 아나요? (단일 선택)
   - 모른다 / 제목만 안다 / 들어 봤다 / 가사와 의미까지 안다
4. 평소에 게임을 하는 시간 (단일 선택)
   - 거의 안 함 / 주 1~5시간 / 주 5시간 이상

분류: 1번에서 '자주 한다' 이상이면 경험자, 그 아래는 비경험자다.

## 3. 판정 로그와 진행자 기록

### 판정 로그 (자동)

전투가 끝나거나 중단될 때마다 빌드가 판정 로그를 자동으로 남긴다(`PrototypeGame.SaveRun` → `BattleLog.Write`). 튜토리얼 판은 남기지 않는다.

- 위치(Windows): `%USERPROFILE%\AppData\LocalLow\DefaultCompany\String As a Sword\BattleLogs\`
- 파일 이름: `battle-<UTC 시각>-<세션번호>.jsonl`
- **진행자는 판마다 시작 시각을 적어 둔다.** 파일 이름의 UTC 시각으로 참가자 번호와 회차를 맞춘다.
- 테스트 전에 폴더를 비우거나 백업한다. 팀원이 플레이한 로그가 섞이면 안 된다.

로그에서 뽑을 값:

| 값 | 용도 (질문 B) |
| --- | --- |
| 결과: Completed / 사망 / 시간 초과 / Interrupted | 클리어율 |
| 판정 오차 분포(입력 시각 − 노트 시각) | 봇 프리셋의 타이밍 오차 σ 보정 |
| Miss ÷ 판정된 노트 | 누락률 보정 |
| 피격한 공격과 그 공격의 예고 길이 | "예고 못 읽음" 비율 보정 |
| 무력화 노트 번호 | 밸런스 목표 v2의 무력화 중앙값 250~285와 비교 |
| 이동·공격·방어 비율 | 봇의 행동 비율과 비교 |
| 사망한 노트 번호 | 어려운 구간 찾기 |

### 진행자 기록 (손으로)

| 항목 | 기록 방법 |
| --- | --- |
| 1회차에 "잡음 수집 → 맨 윗줄 공격"을 스스로 해냈나 | 예 / 아니오 / 튜토리얼 덕분에 |
| 소리 내어 말한 것 중 인상적인 말 | 그대로 받아 적는다. 포스터 인용 후보 |
| 프롤로그·엔딩에서의 반응 | 웃음, 탄성, 무반응, 지루해함 |
| 질문한 것 | 무엇이 설명 없이는 이해되지 않았는지 |

## 4. 1회차 직후 즉시 질문 (1분)

1회차 전투가 끝나자마자 구두로 묻고 진행자가 받아 적는다.

1. 지금 기분을 한 단어로 말해 주세요.
2. 플레이하는 동안 가장 많이 든 느낌은? (보기를 보여 준다: 긴장 / 답답함 / 혼란 / 재미 / 지루함 / 몰입 / 기타)

## 5. 사후 설문

점수 문항은 모두 **1(전혀 아니다) ~ 5(매우 그렇다)** 로 한다. 역방향 문항에는 (역)을 붙였다. 집계할 때는 (역) 문항을 뒤집지 말고 그대로 보고한다.

### A. 감정 곡선 (질문 A)

아래 장면마다 그때의 느낌을 −2(매우 답답함·묶임) ~ +2(매우 시원함·자유로움)로 표시한다. 기억나지 않는 장면은 비워 둔다. 설문지에는 장면마다 대표 캡처 한 장을 함께 넣는다.

| 장면 | −2 | −1 | 0 | +1 | +2 |
| --- | --- | --- | --- | --- | --- |
| ① 프롤로그 — 왕의 현이 나이트를 판에 묶을 때 | | | | | |
| ② 튜토리얼 | | | | | |
| ③ 곡 초반 (정통 체스 공격) | | | | | |
| ④ 곡 중반 (변형된 공격) | | | | | |
| ⑤ 곡 후반 (존재하지 않는 규칙의 공격) | | | | | |
| ⑥ 마지막 3연타로 왕을 쓰러뜨릴 때 | | | | | |
| ⑦ 판이 깨지고 하얀 세계를 걸을 때 | | | | | |
| ⑧ 하얀 메인화면을 봤을 때 | | | | | |

포스터에는 참가자 평균을 선 그래프로 그린다. **기대하는 모양은 ③~⑤에서 낮고 ⑥~⑧에서 크게 올라가는 곡선이다.** 이 그래프 하나가 디자인 명제의 증거가 된다.

### B. 제약의 체감: 의도된 답답함과 부당한 답답함 (질문 A)

| # | 문항 | 종류 |
| --- | --- | --- |
| B1 | 박자에 맞춰서만 움직일 수 있다는 것이 답답했다 | 의도된 답답함 |
| B2 | 맨 윗줄에서만 공격할 수 있다는 것이 답답했다 | 의도된 답답함 |
| B3 | 잡음을 모으지 않으면 공격할 수 없다는 것이 답답했다 | 의도된 답답함 |
| B4 | 이 답답함은 게임이 일부러 만든 것이라고 느꼈다 | 의도 인식 |
| B5 | 판정이 내 입력과 맞지 않는다고 느꼈다 (역) | 부당한 답답함 |
| B6 | 피할 방법이 없는 공격에 맞았다고 느꼈다 (역) | 부당한 답답함 |
| B7 | 무엇을 해야 할지 몰라서 답답했다 (역) | 부당한 답답함 |

판정: B1~B4 평균은 3 이상, B5~B7 평균은 2.5 이하이면 통과다. B6이 높게 나오면 공정성 검증기가 잡지 못한 경우가 있다는 뜻이므로, 진행자 기록과 판정 로그에서 해당 공격을 찾는다.

### C. 해방감과 엔딩 (질문 A)

엔딩을 개발자 무적으로 본 참가자는 '무적으로 봄'에 표시한다.

| # | 문항 |
| --- | --- |
| C1 | 판이 깨지는 순간 해방감을 느꼈다 |
| C2 | 격자도 박자도 없이 하얀 세계를 걸을 때 앞의 플레이와 대비되어 자유롭게 느껴졌다 |
| C3 | 엔딩은 플레이 내내 참은 것에 대한 보상처럼 느껴졌다 |
| C4 | 엔딩 뒤 메인화면이 하얗게 바뀐 것을 알아챘다 (예 / 아니오) |
| C5 | 곡의 끝과 게임의 끝이 맞물린다고 느꼈다 |

### D. 메시지 해석 (질문 C, 의도를 알려 주기 전에)

**D1~D3을 다 쓴 뒤에** 진행자가 곡과 팀의 의도를 한 문단으로 설명하고 D4·D5를 묻는다. 설문 도구에서는 섹션을 나눠 뒤로 돌아가 고칠 수 없게 한다.

- D1. (주관식) 이 게임이 말하려는 것은 무엇이라고 느꼈나요? 한두 문장으로 적어 주세요.
- D2. (주관식) 체스판, 나이트, 왕, 현(검), 잡음은 각각 무엇을 뜻한다고 생각하나요? 아는 것만 적어 주세요.
- D3. 게임의 규칙만으로 어떤 메시지가 전해졌다 (1~5)

> 진행자 설명 예시: "이 게임은 이승윤의 「검을 현」을 바탕으로 만들었습니다. 정해진 규칙, 즉 체스판에 박혀 있지 않겠다는 곡의 메시지를 규칙으로 옮겼습니다. 박자에 묶인 이동과 맨 윗줄에서만 닿는 검은 일부러 만든 제약이고, 마지막에 판을 깨고 나가는 것이 곡의 결말입니다."

- D4. 의도를 듣고 나니 플레이하며 느낀 답답함이 납득된다 (1~5)
- D5. 이 게임을 하고 나서 원곡을 들으면 다르게 들릴 것 같다 (1~5)

D1·D2는 팀원 2명이 따로 아래 기준으로 분류하고, 판단이 갈리면 합의한다.

| 분류 | 기준 |
| --- | --- |
| 일치 | "규칙·틀·속박에서 벗어남"이라는 핵심을 말함 |
| 부분 일치 | 속박이나 저항 중 하나만 말함 |
| 불일치 | 다른 해석, 또는 "모르겠다" |

포스터에 쓸 숫자는 **곡을 모르는 참가자(2절 3번 '모른다' 또는 '제목만 안다') 중 '일치'의 비율**이다. 곡을 아는 참가자는 원래 의미를 알고 답할 수 있으므로 따로 보고한다.

### F. 연출과 사운드 (미디어 부문)

| # | 문항 |

F4는 포스터의 '남은 것'(판정 표시, 타격 VFX)과 연결된다. 낮게 나오면 테스트 뒤 가장 먼저 고칠 항목의 근거가 된다.

3. 설명이 없어서 이해가 안 된 것은?
4. 하나만 바꿀 수 있다면 무엇을 바꾸겠나요?

## 6. 판단 기준

아래 값은 이 문서에서 제안하는 것이다. 팀이 확정한 수치가 아니므로 테스트 전에 합의한다.

| 질문 | 통과 기준 | 미달이면 |
| --- | --- | --- |
| A. 감정 곡선 | ⑥~⑧ 평균이 ③~⑤ 평균보다 1.5 이상 높음 | 엔딩 쪽이 낮으면 엔딩 연출을, 플레이 쪽이 높으면(덜 답답하면) 제약의 전달을 본다 |
| A. 의도된/부당한 답답함 | B1~B4 평균 ≥ 3, B5~B7 평균 ≤ 2.5 | B5가 높으면 싱크·판정 창, B6이 높으면 해당 공격 패턴, B7이 높으면 튜토리얼을 고친다 |
| A. 해방감 | C1·C3 평균 ≥ 4 | 엔딩 진입 연출(3연타 → 균열 → 터짐)의 길이와 소리를 다시 본다 |
| B. 클리어율 (3회차 안에 1번 이상) | 어려움 경험자 60~80%, 쉬움 비경험자 50~70% | 봇 목표와 같은 범위다. 벗어나면 3절 로그로 원인을 찾고 프리셋을 보정해 시뮬레이션을 다시 돌린다 |
| B. 봇 예측 오차 | 사람 클리어율이 같은 그룹 봇 예측의 ±15%p 안 | 벗어나면 로그의 판정 오차·누락률로 `SkillProfile`을 고치고 결과를 [Battle11Balance.md](Battle11Balance.md) 뒤에 덧붙인다 |
| C. 메시지 전달 | 곡을 모르는 참가자 중 '일치' + '부분 일치' ≥ 50% | 프롤로그의 속박 장면이나 엔딩의 대비를 강화한다 |
| 종합 | G1·G2 평균 ≥ 4, G3 평균 ≥ 7 | H 주관식에서 가장 많이 나온 불만부터 고친다 |

## 7. 포스터에 옮길 결과

결과 문서는 `Docs/Playtest-1.0-Results.md`로 만들고 6절 표에 실제 값과 판정을 채운다. 포스터에는 아래 다섯 가지만 옮긴다.

1. **감정 곡선 그래프**(5절 A): "답답함이 엔딩에서 해방감으로" — 디자인 명제의 증거.
2. **사람 vs 봇 클리어율 막대그래프**: 그룹별로 나란히 놓는다. 예측이 맞았다면 "봇 시뮬레이션이 사람을 ±N%p로 예측"이라고 쓴다. 이 결과는 '활용방안'의 "밸런스 비용 절감" 주장을 뒷받침한다.
3. **메시지 전달률**: "곡을 모르는 참가자의 N%가 규칙만으로 '판을 벗어남'을 읽어 냄".
4. **대표 인용 1~2개**: 3절 진행자 기록이나 5절 H에서 고른다.
5. **참가자 수와 구성**: "n = N (리듬게임 경험자 a, 비경험자 b)".

포스터의 '남은 것'에서 "사람 대상 플레이테스트"를 지우고, 테스트에서 나온 다음 개선 과제(예: F4가 낮으면 타격 VFX)로 바꾼다.

## 8. 테스트 전에 끝낼 일

| 순서 | 할 일 |
| --- | --- |
| 1 | Windows 빌드를 새로 만들고 전체 흐름(메인화면 → 프롤로그 → 튜토리얼 → 전투 → 엔딩 → 흰 메인화면)을 한 번 끝까지 돈다 |
| 2 | 테스트 PC의 `BattleLogs` 폴더를 비우고, 한 판을 해서 로그가 생기는지 확인한다 |
| 3 | 테스트 PC에서 입력 싱크·화면 싱크를 맞춘다. 싱크가 틀리면 판정 데이터와 B5 응답이 모두 오염된다 |
| 4 | 메인화면에서 Shift+R로 클리어 기록을 지운다. 참가자마다 어두운 메인화면에서 시작해야 C4가 의미 있다 |
| 5 | 설문을 Google Forms 같은 도구로 옮긴다. 5절 D는 D1~D3과 D4~D5를 다른 섹션으로 나누고, 5절 A에는 장면 캡처를 넣는다 |
| 6 | 참가자 동의서: 익명 처리, 화면·음성 녹화 여부, 결과를 포스터와 발표에 쓴다는 점 |
