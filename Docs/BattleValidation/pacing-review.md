# 랜덤 전투 통합 검토

범위: 기준 6291cc2 이후 db58472(HP), 25a7c05(스케줄·판정·로그), 20d05a0(비교 도구), efdf5bc(입력 테스트 격리), 8318e4e(실제 화면·빌드). 기존 사용자 음원·렌더·프로젝트 설정 변경은 검토/커밋 대상에서 제외했다.

`ponytail-review`를 적용한 주 에이전트 검토와 별도 읽기 검토에서 변경 함수의 BattleSession 호출부, Stage 직렬화, Observation, SafeRoutePlanner, 테스트, 로그 재현, 고정 비교/화면 fixture를 확인했다. 비교 도구는 기존 BattleSimulator를 재사용하며 기본 1,000개 시드/총 27,000세션의 부하를 기준으로 검토했다.

발견 후 수정한 문제:

1. 페이즈 전환이 발동 노트와 겹칠 때 BeginPhase에서 LastFired를 비우면 실제 발동 표시가 사라진다. 해당 노트의 LastFired를 다음 Resolve까지 보존하고 회귀 테스트를 추가했다.
2. 간격 설정의 시작값과 가중치 길이를 따로 검증하면 최종 간격이 허용 범위를 넘을 수 있다. 마지막 인덱스까지 포함한 4~16 범위를 검증하고 잘못된 설정을 거부하는 테스트를 추가했다.
3. 실제 키보드 A/S가 PlayMode의 합성 W 입력에 섞여 두 테스트가 실패했다. 테스트 중 기존 Unity Input System 키보드만 비활성화하고 원래 활성 상태를 teardown에서 복원한다. 런타임 입력 정책은 바꾸지 않았다. 재실행 7/7 통과.
4. 화면 fixture에서 From 반환 설정의 Schedule 참조를 직접 바꾸면 Stage의 메모리 설정도 바뀐다. fixture는 설정을 복사한 뒤 고정/랜덤 모드를 선택한다. 실제 화면 검증 후 Stage.Enabled=true를 확인했다.

EditMode 101/101, PlayMode 7/7, 비교 실행기 병렬 스모크 108회·불변식 오류0·재현81/81을 확인했다. 늦은 Good, 단일 행동, 위협 합집합, 정확한 경고 감소, 독립 난수, 제한된 재시도, 이전 잡음 경로, 이전 공개 예고 불변, 조기 종료 합계, 노트/이벤트 재현을 포함한다. 실제 발동 간격 16 초과는 안전성 연기로 허용하며 별도 로그·통계·테스트로 보존한다.

잔여 한계: 비교 도구는 전체 세션 대신 작은 통계 객체만 유지하지만 count 상한 100,000까지의 메모리는 측정하지 않았다. 기본 count=1,000을 사용하며 대규모 확대 시 그룹별 통계 집계 후 해제 또는 스트리밍 집계가 필요하다. BFS 전개 상태 수와 목표 하드웨어 프레임 시간은 별도 계측하지 않았다. 기존 저장소에 없는 Original/Special 선택 UI나 개별 노트 편집기를 검증했다고 주장하지 않는다.

실제 화면과 Windows 실행 결과는 [화면 검증](../BattleVisual/Pacing/Verification.md), [빌드](pacing-build.json), [실행 진단](pacing-standalone.json)에 기록했다. 전체 27,000회 비교가 완료됐으며 불변식 오류 0건, 대표/첫 실패 333개 재현 불일치 0건이었다. [측정 보고서](../BattlePacing/Results.md)에 실패를 포함한 결과와 해석을 기록했다. HP만 절반인 구성보다 랜덤 구성의 최장 공격 연속이 늘어난 결과도 숨기지 않았다.
