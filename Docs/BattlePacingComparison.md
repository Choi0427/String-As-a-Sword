# 보스 공격 간격 비교 도구

`Assets/_Project/Editor/BattlePacingComparison.cs`는 실제 전투와 같은 `BattleSimulator.Run` → `BattleSession`을 실행합니다. 독립적인 간이 전투 모델을 만들지 않으며, 기존 관찰 전용 세 전략을 그대로 사용합니다. HP 보정과 설정 저장은 수행하지 않습니다.

## 비교 구성과 표본

| 구성 | HP | 패턴 |
| --- | --- | --- |
| A-original | 62/12/24/94 | `PatternDefinition.Defaults()`와 고정 반복 모드 |
| B-half-hp | 31/6/12/47 | A와 같은 고정 패턴 |
| C-random-half-hp | 31/6/12/47 | 현재 저장된 랜덤 패턴 설정 |

A/B도 현재 런타임에서 실행합니다. 과거 실행 파일 자체와의 이진 비교는 아닙니다. C의 HP가 위 값과 다르거나 랜덤 스케줄이 비활성화되어 있으면 실행을 거부합니다. 모든 실행은 실제 HP와 수집 조건으로 페이즈가 바뀌며, 분석 전용 가상 페이즈 구간을 사용하지 않습니다.

기본 `count=1000`은 각 구성·전략에 대해 개발 시드 0~999, 독립 시드 100000~100999, 동일 독립 시드의 입력 누락 5% 세 집합을 실행합니다. 총 3구성 × 3전략 × 3집합 × 1,000 = 27,000회입니다. 누락 난수는 전투 난수와 분리되어 있습니다. 이 도구는 결과를 보고 자동으로 HP나 스케줄을 바꾸지 않습니다.

## 실행

Unity Editor의 메인 스레드에서 설정을 읽습니다.

```csharp
var settings = StringAsASword.Editor.BattleAnalysis.LoadSettings();
```

그 후 다음 호출은 백그라운드 작업에서 실행할 수 있습니다. 설정의 복사본을 사용하고 AssetDatabase를 호출하지 않습니다.

```csharp
StringAsASword.Editor.BattlePacingComparison.Run(
    settings, "Logs/BattlePacingComparison", 1000);
```

동기 소규모 확인은 `BattlePacingComparison.Run("Logs/BattlePacingSmoke", 2)`로 54회를 실행합니다. 실행 시작 시 `SelfCheck()`가 분위수, 행동/페이즈 합계, 페이즈 경계를 넘는 공격 연속, 회피+수집 집계, CSV 이스케이프를 검증합니다. 이전 로그와 새 결과가 섞이거나 덮어쓰이지 않게 비어 있지 않은 출력 디렉터리는 거부합니다. 실험마다 새 출력 디렉터리를 쓰세요.

`progress.txt`는 100회마다 갱신됩니다. 실패한 실행도 계속 기록하며, 게임에서 생긴 사망과 시간 초과를 도구 실패로 처리하지 않습니다. 전투 실행 자체에서 예외가 발생하면 실행이 중단되고 완성된 성공 보고서를 쓰지 않습니다.

실행은 32개 세션 단위로 나누고 `BattleSimulator.Run` 계산만 최대 네 작업자(CPU가 더 적으면 해당 수)에서 병렬 수행합니다. 공유 보드와 이동 방향 목록은 읽기 전용이고, 전투 상태와 난수는 세션마다 분리됩니다. CSV 집계·로그 저장·재현 검사는 시드 순서대로 직렬 처리하므로 파일 행 순서를 유지하며, 최대 32개 세션만 동시에 보관합니다. SelfCheck는 같은 시드의 병렬 실행과 직렬 실행에서 노트 상태 및 이벤트가 같은지도 확인합니다. `simulation_ms`는 각 실행의 벽시계 시간으로, 병렬 실행 중 CPU 경쟁의 영향을 받습니다.

## 산출물과 해석

- `summary.json`, `BattlePacingComparison.md`: 실행 수·실패 수·재현 결과와 주요 비교표.
- `runs.csv.gz`: 실패 포함 모든 실행. 처리/잔여 노트, 사망/목표 미달, 피격/방어/회피+수집, 공격 연속, 발동/연기/거부/생략, 실제 간격, 실행 시간.
- `phases.csv.gz`: 모든 실행의 네 페이즈. 이동/방어/유효 공격/기타, 공격 기회/실제 피해, 전환 노트, 목표 미달.
- `events.csv.gz`: 모든 패턴·잡음 이벤트. 범위·공개/발동 노트·예고 길이·회피 행동 수·선택/실제 간격·거부 이유.
- `distributions.csv`: 전체 및 페이즈별 min/P10/P50/P90/max/mean.
- `frequencies.csv`: 패턴 종류·공격 범위·예고·간격·거부 이유별 빈도.
- `logs/*.jsonl.gz`: 각 집합/구성/전략의 첫 3개, 이후 매 100번째 표본, 모든 사망·시간 초과·불변식 실패 기록.

`transition_note`와 `clear_note`는 화면과 같은 1부터 시작하는 노트 번호입니다. 미전환/미클리어는 -1입니다. 원시 이벤트 `note_index`와 `impact_note`는 기존 로그와 같은 0부터 시작하는 내부 인덱스입니다. 미진입 페이즈는 행동 0과 미수집 목표를 보존합니다. 클리어 노트 분위수만 성공 실행으로 한정하고 표본 수와 사망/시간 초과를 함께 보고합니다. 나머지 행동·종료 시점 통계에서는 실패를 제외하지 않습니다.

실제 공격 간격은 서로 다른 발동 노트의 차이입니다. 같은 노트의 중첩은 한 발동 시점으로 계산하고, 페이즈 전환을 가로지르는 휴식도 포함합니다. 16 초과 간격은 별도 집계합니다. 짧은 간격 연속은 5 이하, 긴 간격 연속은 12 이상으로 정의합니다. 유효 공격의 연속과 헛공격을 포함한 모든 공격 행동의 연속을 나눠 기록합니다.

회피+수집은 해당 노트에 출발 칸이 발동 범위이고 도착 칸이 범위 밖이며 실제 수집한 이동만 셉니다. 단순 수집 이동을 회피로 부풀리지 않습니다. 탐색 비용은 실행 시간과 후보 거부·연기 횟수로 보고합니다. BFS 내부 전개 수는 계측하지 않았으며, 거부 횟수는 전개 수가 아닙니다.

## 재현과 검증 범위

```csharp
var replay = StringAsASword.Combat.BattleLog.Replay(
    "Logs/BattlePacingComparison/logs/holdout-C-random-half-hp-CollectFirst-100000.jsonl.gz");
```

대표 표본과 각 그룹의 첫 실패는 저장 직후 자동 재현합니다. 기존 재현 검사의 노트·최종 상태에 더해 모든 이벤트의 직렬화 해시를 대조합니다. 재현 오류는 숨기지 않고 `summary.json`과 보고서에 남깁니다. 버전이 다른 과거 로그는 해당 버전에서 재현해야 합니다.

사용 스킬은 `ponytail(full)`(기존 시뮬레이터 재사용·불필요한 모델 분리 방지), `unity` 및 CLI 가이드(메인 스레드 설정 읽기와 실제 에디터 통합), `ponytail-review`(변경된 도구의 호출부·샘플 보존·집계 경계·저장 비용 검토)입니다. 자동 표본 통과는 전 경우의 공정성 증명이나 사람의 재미 검증이 아닙니다. 실제 실행 결과는 출력 보고서와 검증 결과를 확인해야 합니다.
