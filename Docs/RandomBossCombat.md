## 설정과 규칙

`Assets/_Project/Data/Stages/FourPhasePrototype.asset`의 Inspector에서 편집한다.

- Health Segments: **31 / 6 / 12 / 47**, 합계 96. 기존 62/12/24/94의 정확한 절반이며 이번 실험에서 자동 재보정하지 않는다.
- Player Max Hp: 3. 시험값이다. 수집 목표 3/4/5, 8음악박 생성, 상한 2, 단계 전환의 HP·수집 AND 조건은 유지한다.
- Attack Schedule.Enabled: 새 전역 스케줄. 끄면 기존 패턴별 FirstImpact/RepeatNotes를 사용한다. 비교 A/B와 기존 고정 패턴 테스트에 필요하다.
- MinInterval: 4. IntervalWeights의 인덱스 0은 4노트, 마지막 인덱스 12는 16노트다. 기본 `[1,1,5,5,5,1,1,1,1,1,1,1,1]`: 6/7/8의 합산 확률 60%, 평균 8.56. 간격 범위는 4~16 안에서만 편집 가능하고 0 가중치는 해당 간격을 제외한다.
- Patterns.SelectionWeight: 해당 페이즈의 Enabled 패턴 중 가중 선택. 기본 세 종류는 동일 가중치 1. Top은 기존대로 페이즈 2~4에서만 사용한다. 같은 종류의 연속 선택은 허용한다. 임의의 연속 선택 억제 규칙은 추가하지 않았다.
- 행/열 패턴은 방향을 반반으로 선택한 뒤 8개 행/열 중 하나를 선택한다. 최상단 압박은 ColumnCount(기본 4) 길이의 연속 구간 시작점을 가능한 위치 전체에서 선택한다. 기존 Coordinate/FirstColumn은 고정 모드에서 사용한다. 위치 고정 공격은 공개 순간 플레이어 칸이다.
- Patterns.TelegraphNotes: 새 모드의 기본 읽기 여유. 현재 행/열 2, 위치 고정 1, 최상단 압박 3. MinWarning/MaxWarning(1/3) 안으로 제한한다. 현재 단일 행·열·셀 형태는 위험 칸에서도 보통 한 칸으로 벗어날 수 있으므로 2/3노트가 이동에 반드시 필요하다고 해석하지 않는다.
- CandidateAttempts: 한 공개 시점에 최대 16개 범위를 검사한다. MaxDeferrals: 같은 예약을 최대 8번 한 노트씩 미룬 뒤 생략하고 새 간격을 선택한다. 연기 중에도 다음 노트 판정은 정상 처리한다.

간격은 발동 노트 간 차이이다. 난수로 선택한 간격과 실제 발동 간격을 모두 기록한다. 첫 공격은 첫 노트 직전의 가상 완료 지점에서 선택한 간격 이후다. 페이즈 전환 때 공개 중인 이전 예고는 취소하며, 이전에 발동한 노트와 충분한 새 예고 시간을 함께 고려한다. 잡음 대기·안전성 검사·페이즈 전환 때문에 실제 간격은 16을 넘을 수 있다. 이를 로그나 통계에서 16으로 잘라 표시하지 않는다. 실제 발동 간격의 상한보다 충분한 경고와 수집 경로를 우선한다.

## 공정성·처리 순서

패턴/간격 예약은 비공개다. 범위는 공개 순간에만 정하고 이후에는 범위·마감 노트를 변경하지 않는다. 패턴 난수는 `seed ^ 0x36d9f1ab`로 분리한 xorshift32 스트림을 사용한다. 잡음의 난수열을 직접 소비하지 않는다. 다만 패턴이 공개된 안전 후보 집합을 바꾸면 같은 잡음 난수로도 실제 위치가 달라질 수 있다.

`BossPatternSystem.DodgeActions`는 최대 3개 시간 단계 × 64칸에서 상하좌우 이동과 제자리 방어 대기를 검사한다. 이동으로 해당 시점의 기존 위험 칸에 착지할 수 없고, 제자리 방어는 기존 공격을 막는 데 한 행동을 쓴다. 마지막 칸은 새 공격과 같은 시점의 합쳐진 위험 범위 밖이어야 한다. 시작 위치가 이미 안전하면 필요한 회피 행동 수는 0이다. 더 긴 대응이 필요하면 아직 공개하지 않은 후보의 예고를 최대 3까지 늘리고 재검사한다. 그 안에서 찾지 못하면 후보를 거부한다.

기존 `CanPublish`는 모든 현재 잡음을 같은 경로에서 수집하고 최상단으로 복귀할 수 있는지 재검사한다. 후보 검사 실패는 제한된 탐색에서 경로를 찾지 못했다는 뜻이며 수학적인 불가능성 증명이 아니다. 정상 설정은 최소 간격 4, 최대 예고 3이므로 새 모드에서는 공개 예고가 서로 겹치지 않는다. 기존 고정 모드의 중첩 대응 검사는 유지한다.

행동·수집은 입력 인정 시 즉시 반영한다. 판정 창 종료 후 플레이어 공격 → 보스 공격/피격 → HP·수집 조건 전환 → 종료 순서를 유지한다. 정상 늦은 Good 이동/방어, 노트당 한 행동, 노트 귀속 방어, 중첩 피해 최대 1, 마지막 노트 Timeout, 동시 최종 처치/사망 시 승리 우선도 유지한다. 전환 노트의 실제 발동 X 표시는 다음 판정까지 보존한다.

## 로그·재현

런타임은 `battle-3/xorshift32-v1`, 설정 버전은 battle-3이다. 과거 battle-1/2 로그는 각각 해당 커밋의 런타임에서 재현해야 한다. 새 `BattleLog.Replay`는 모든 입력에서 노트·최종 상태뿐 아니라 전체 이벤트도 다시 생성해 비교한다.

패턴 이벤트는 `publish/fire/reject/defer/skip/cancel`. 공통으로 kind, cells, impactNote, warningNotes, requiredDodgeActions, selectedInterval, actualInterval, reason을 기록한다. 범위를 확정하지 않은 연기·생략 이벤트의 cells는 후보 진단값이며 공개 예고가 아니다. requiredDodgeActions=-1은 경로 미확인 또는 검사 실패다. 첫 발동의 actualInterval=0은 이전 발동 없음이다. 고정 모드 비교의 실제 간격은 fire 노트 차이로 다시 계산한다.

거부/연기 이유는 `no-dodge-within-warning`, `disclosed-route`, `pickup-route`, `noise-wait`이며 `chart-end` 또는 `retry-limit:이유`로 생략할 수 있다. 전투의 공용 Observation에는 미래 예약·seed·RNG가 없다.

비교 도구 실행 및 원자료 구조는 [BattlePacingComparison.md](BattlePacingComparison.md)를 참조한다. 기본 실행은 세 구성 × 세 전략 × 개발/독립/5% 누락 집합 × 1,000개 시드 = 27,000회이다. HP·패턴을 결과에 맞춰 자동 수정하지 않는다.

## 검토와 사람 플레이

unity(실제 Unity 6000.5.5f1, CLI 1.0.0-beta.14 연결·컴파일·테스트), unity의 ui/ui-ugui(기존 Canvas 및 카메라 예고 검증), ponytail full(기존 전투·입력·생성·시뮬레이터 재사용), ponytail-review(변경 함수와 호출부·설정·로그·테스트)를 적용했다. 보조 에이전트는 회귀 테스트, 비교 실행기, 독립 읽기 검토를 맡았다.

사람 플레이에서는 1노트 위치 고정 예고의 인지 시간, 숫자와 플레이어의 동시 식별, 방어와 회피의 선택 이유, 수집과 회피의 결합, 4페이즈 반복감, 긴 휴식과 연속 짧은 간격의 체감, 곡 중간 클리어가 만족스러운지 확인해야 한다. 자동 입력 누락 5%는 사람의 반응 지연·오판 모형을 대체하지 않는다. 최종 실행 결과와 미검증 사항은 별도 측정 보고서에 기록한다.
