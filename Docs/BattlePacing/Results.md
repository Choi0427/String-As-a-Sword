# 보스 전투 변경 및 27,000회 비교 결과

2026-10-23 · Unity 6000.5.5f1 · Unity CLI 1.0.0-beta.14 · battle-3/xorshift32-v1

**HP 절반과 랜덤 전역 공격 스케줄을 구현했다. 전투는 크게 짧아졌지만, 랜덤화가 긴 공격 반복을 줄였다고 결론 내릴 수는 없다.** 독립 시드의 클리어 중앙값은 178~185노트다. HP만 절반으로 줄인 구성보다 최장 연속 공격은 길어졌고, 입력 누락 5%에서 사망률은 높아졌다. 요청한 설정은 그대로 저장했으며 측정 결과에 맞춰 몰래 HP를 보정하지 않았다.

## 구현과 편집

- HP: 기존 62/12/24/94 → **31/6/12/47**, 총 192 → 96. 산식은 각 기존 HP ÷ 2이며 모두 정수라 반올림이 없다. 이번 값은 사용자가 지정한 절반 값이며 새 P10 예산 보정으로 얻은 값이 아니다.
- 전역 공격 간격: 4~16노트 가중 추첨. 6/7/8 각각 가중치 5, 나머지는 1로 합산 60%를 배정했다. 패턴마다 따로 반복해 전역 간격이 무너지는 방식은 사용하지 않는다.
- 패턴: 페이즈에서 허용된 종류를 가중 선택한다. 행/열의 방향과 위치, 최상단 연속 구간을 무작위로 정한다. 위치 고정 공격은 예고 공개 순간의 플레이어 칸으로 고정한다. 패턴 난수와 잡음 난수는 분리했다.
- 예고: 1~3노트. 현재 기본 읽기 여유는 행/열 2, 위치 고정 1, 최상단 3이다. 시간별 안전 이동·방어 대기를 검사하고 필요한 대응 시간이 부족하면 공개 전에 늘리거나 후보를 거부한다. 공개 후 범위와 발동 노트는 바꾸지 않는다.
- 수집 경로: 기존 잡음을 수집하고 복귀하는 경로를 보존하는 후보만 공개한다. 한 시점 최대 16후보·8회 연기 후 생략하여 무제한 탐색을 막는다.
- 노트당 한 행동, 늦은 Good 이동/방어, 노트 귀속 방어, 중첩 피해 상한, 처리 순서, 8음악박 잡음 주기·상한 2·목표 3/4/5, 마지막 노트 Timeout을 유지했다. 페이즈 전환과 같은 노트의 발동 표시가 사라지는 문제도 수정했다.

설정은 `Assets/_Project/Data/Stages/FourPhasePrototype.asset`의 Health Segments, Attack Schedule, Patterns에서 편집한다. `Attack Schedule.Enabled=false`이면 기존 고정 패턴 모드를 사용한다. 필드의 의미·허용 범위·공정성 우선순위는 [설정 설명](../RandomBossCombat.md)에 있다. 변경 전 사용자가 수정한 음원·음량·렌더·프로젝트 설정 파일은 이 작업의 커밋에 포함하지 않았다.

주요 코드:

- `Scripts/Combat/BattleSettings.cs`, `BossPatternSystem.cs`: 설정·독립 난수·전역 예약·범위/회피/수집 경로 검증.
- `Scripts/Combat/BattleSession.cs`, `BattleLog.cs`: 실행 연결, 패턴 메타데이터, 전체 이벤트를 포함한 재현 비교.
- `Scripts/Stage/StageDefinition.cs`, `Data/Stages/FourPhasePrototype.asset`: Inspector 설정과 실제 저장값.
- `Editor/BattlePacingComparison.cs`: 기존 실제 전투 세션을 사용하는 A/B/C 비교 및 원자료 출력.
- `Tests/EditMode/RandomBossPatternTests.cs`, PlayMode 입력 테스트, `Editor/BattleVisualVerification.cs`: 경계·결정론·키보드 격리·실제 화면 fixture.

위 경로의 기준은 `Assets/_Project/`이다.

## 비교 설계와 실행

| 구성 | HP | 공격 |
|---|---|---|
| A 원본 | 62/12/24/94 | 기존 고정 반복 |
| B HP 절반 | 31/6/12/47 | A와 동일 |
| C 최종 | 31/6/12/47 | 새 랜덤 전역 스케줄 |

각 구성에서 수집 우선(CollectFirst), 공격 유지(AttackHold), 이동 활용(MovementUse)을 실행했다. 세 전략 모두 공개 Observation만 사용한다. 미래 예약·난수·시드는 플레이어 관찰에 노출하지 않는다. A/B도 현재 battle-3 런타임의 고정 모드이며 과거 실행 파일 자체를 비교한 것은 아니다.

개발 시드 0~999, 조정에 쓰지 않은 독립 시드 100000~100999, 독립 시드에 입력 누락 5%를 적용한 집합을 각각 실행했다. 총 **3 × 3 × 3 × 1,000 = 27,000회**, 약 933초였다. 입력 누락 난수는 전투 난수와 별개다. 사망을 제외하지 않았으며 시간 초과는 모든 집합에서 0건이었다. 동일 시드 번호라도 구성에 따라 공개 경로·선택·난수 소비 시점이 달라지므로 동일 위치의 공격을 짝지은 실험은 아니다.

현재 저장된 EvenNotes 채보는 344개/87 BPM이며 내용 해시는 `fca0ddae34240a311efe3259391acdaee1e7633a4e071a4203720f32cfe0a960`이다. 채보를 다시 생성하거나 판정 창을 바꾸지 않았다. 분석 전용 가상 기회 수 **100/48/68/128**은 기존 분석에 유지하며, 이번 전체 비교에서는 실제 HP·수집 조건으로 전환한다. 가상 경계를 게임의 강제 전환이나 음악 구간으로 해석하지 않는다.

분위수는 nearest rank `ceil(q × N)`이다. 아래 클리어 노트만 성공 실행의 분포이고 사망 수를 함께 표시한다. 행동량·종료 통계는 실패를 포함한다. 전체 27그룹과 모든 분포는 [생성된 비교표](Full/BattlePacingComparison.md), [분포 CSV](Full/distributions.csv)에 있다.

## 전체 클리어와 반복감

입력 누락 없는 독립 집합은 A/B/C의 모든 전략이 각각 **1,000/1,000 클리어**, 피격 0회였다.

| 전략 | A 클리어 중앙값 | B 중앙값 | C P10 / 중앙값 / P90 | 최장 유효 공격 연속 평균 B → C | 방어 성공 평균 B → C |
|---|---:|---:|---:|---:|---:|
| 수집 우선 | 289 | 181 | 171 / 182 / 193 | 20.52 → 26.45 | 0.15 → 0.13 |
| 공격 유지 | 281 | 180 | 173 / 185 / 196 | 22.04 → 25.33 | 5.59 → 10.63 |
| 이동 활용 | 287 | 179 | 167 / 178 / 192 | 21.37 → 25.07 | 0.16 → 0.14 |

최장 공격 연속은 페이즈 경계를 가로질러 이어지는 공격도 포함한다. C의 4페이즈 안에서만 측정한 최장 연속 평균도 23.34~23.63노트다. 최상단 전체를 지속해서 위협하지 않는 랜덤 위치와 방어 가능한 패턴 특성상, 공격 기회가 길게 이어질 수 있다. 따라서 **전투 길이 단축은 확인됐고, 긴 공격 반복 제거는 확인되지 않았다.** 방어 유지 전략의 대응 압박은 늘었다.

최종 C의 남은 행동 기회는 평균 159.17~164.96개다. 이는 조기 클리어 후 사용하지 않은 기회이며, 모두 즉시 가할 수 있었던 추가 피해량을 의미하지 않는다. HP 총량을 96으로 고정했으므로 남은 곡의 상당 부분 전에 종료한다. 이것이 원하는 플레이 길이인지는 사람 플레이로 확인해야 한다.

정지 플레이를 살핀 별도 대표 표본은 전략별 12시드뿐이다. 공격 유지 전략은 4페이즈에서 가장 오래 머문 한 칸의 점유율이 평균 95.1%였다. 가장 많이 머문 칸은 실행마다 달랐으며 보편적인 한 안전 칸이 입증된 것은 아니다. 수집 우선은 54.4%, 이동 활용은 57.1%였다. 원자료는 [위치 표본](Full/position-sample.json)에 있다. 이 값은 1,000시드 전체의 통계가 아니다.

| 공격 유지 | 972 / 28 | 998 / 2 | 983 / 17 | 181 / 193 / 207 | 6 |
| 이동 활용 | 964 / 36 | 994 / 6 | 987 / 13 | 174 / 188 / 203 | 5 |

각 셀의 분모는 1,000이다. C의 48사망 중 페이즈별 발생은 1/6/8/33건이었다. 수집 미달은 사망과 겹치는 진단값이며 추가 실패 수가 아니다. C는 B보다 사망이 13→48건으로 늘었다. 입력 누락은 Miss 자체의 추가 피해가 아니라 해당 노트의 공격 대응을 놓치는 방식으로 손실을 만든다. 이 모형은 사람의 반응 지연·잘못된 방향 입력·예고 오독을 재현하지 않는다.

## 실제 스케줄과 탐색 비용

독립 C 3,000회의 실제 발동 간격은 총 59,015개이며 평균 **8.55노트**, 6~8노트 비율 **59.98%**였다. 16 초과는 **243개(0.412%)**, 최대 39노트였다. 무작위 선택 범위 4~16과 안전성/페이즈 취소·연기로 생긴 실제 발동 간격은 다르다. 충분한 예고와 기존 잡음 경로 보존을 우선하며 이 차이를 숨기거나 16으로 잘라 집계하지 않는다.

공개된 예고는 1노트 23,547개, 2노트 23,910개, 3노트 15,814개였다. 공개 종류는 행 12,022 / 열 11,888 / 위치 고정 23,547 / 최상단 15,814개다. 최상단은 페이즈 2~4에서만 허용되며 공개 후 페이즈 종료로 취소될 수 있어 발동 횟수와 같지 않다. 실제 설정에서 필요한 회피 행동은 0 또는 1이었다. 기본 2/3노트는 읽기 여유이며, 2~3행동이 필요한 합성 경계 사례는 별도 테스트했다.

독립 C에서 잡음 연기·대체·생성 불가 이벤트는 0건이었다. 그 경계는 별도 테스트로 검증했다. 패턴 쪽에서는 잡음 경로 보존 때문에 후보 거부 88,455회, 연기 5,439회, 연기 한도 후 생략 88회가 기록됐다. 이는 후보 수이며 실패한 게임 수나 BFS 전개 상태 수가 아니다.

|---|---:|---:|---:|---:|
| 수집 우선 | 79.15 / 157.01 | 11.57 | 0.689 | 0.034 |
| 공격 유지 | 136.81 / 249.53 | 29.34 | 1.832 | 0.001 |
| 이동 활용 | 137.47 / 244.28 | 47.55 | 2.918 | 0.053 |

계산 시간은 최대 네 작업자의 병렬 오프라인 실행이며 목표 하드웨어 프레임 지연이 아니다. BFS 내부 전개 수는 계측하지 않았다. 기본 1,000시드에서 완료했지만 도구의 명목상 100,000시드 상한 메모리는 검증하지 않았다.

## 실행·재현·원자료

[실행 가이드](../BattlePacingComparison.md)의 `BattlePacingComparison.Run(settings, output, 1000)`으로 다시 실행한다. 설정 읽기는 Editor 메인 스레드에서, 계산은 복사한 설정으로 수행한다. 출력은 새 빈 폴더를 지정한다.

```csharp
var result = StringAsASword.Combat.BattleLog.Replay(
    "Docs/BattlePacing/Full/logs/miss5-C-random-half-hp-MovementUse-100045.jsonl.gz");
```

`Full/`에는 전체 27,000회의 runs/phases/events 압축 CSV, 분포·빈도·요약, 성공/실패 재현 6개와 SHA-256 [manifest](Full/manifest.json)를 보존했다. 원 실행의 로그 486개는 `Logs/BattlePacing/full/logs/`에 있다. 이 원 실행 폴더는 Git 대상이 아니므로 다른 체크아웃에서는 선택한 6개 외 로그를 재생하려면 같은 실행을 생성해야 한다. 재현은 같은 battle-3 런타임을 사용하며 과거 battle-1/2 로그는 당시 커밋이 필요하다.

## 남은 한계와 사람 플레이 확인

현재 저장소에는 별도의 Original/Special 선택 UI와 개별 노트 편집기가 없어 그 회귀를 통과했다고 보고하지 않는다. 기존 단일 SongDefinition 편집·시작 경로는 유지했다. 다른 화면 크기/해상도, 목표 기기의 프레임 지연, 모든 시드의 수학적 공정성, 사람의 재미는 검증하지 않았다.

사람 플레이에서는 다음을 확인한다.

1. 1노트 위치 고정 예고를 실제 곡 속에서 인식하고 반응할 시간이 충분한가.
2. 회피·방어·수집 중 선택의 이유가 생기는가. 방어로 오래 제자리 공격해도 여전히 지루한가.
3. 4페이즈의 20노트 이상 연속 공격과 실제 16초과 휴식이 눈에 띄는가.
4. 178~185노트 부근의 조기 종료가 원하는 전투 길이인가, 곡을 더 듣고 싶게 만드는가.
5. 5% 누락 모형에는 없는 방향 실수·늦은 입력·예고 오독에서 체력 3이 지나치게 가혹한가.

다음 변경은 이 결과와 사람 플레이를 보고 정한다. 긴 공격 반복을 반드시 끊고 싶다면 최상단 위협 분포나 압박 배치를 별도 실험해야 한다. 이번 구현에서는 요청 범위를 넘어 방어 불가 공격·강제 이동·추가 HP 변경을 넣지 않았다.
