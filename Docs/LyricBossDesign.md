# 가사 연동 보스 설계와 RCM 보스 채보

2026-11-12 작성, 같은 날 수정(도약 노트 제거 → 싸비 "ㅈㅈ" 전진 구간). **설계 문서이며 구현·측정은 하지 않았다.** 현재 설정(battle-4)의 규칙은 [BossPatternVariety.md](BossPatternVariety.md)와 [BossCombat.md](BossCombat.md)를 따른다. 이 문서의 수치(반격 피해, 일격 위력, 보스 HP 등)는 모두 미정이며 `BattleAnalysis` 재측정으로 정한다.

곡 「검을 현」의 구간(간주·벌스·브릿지·싸비·Interlude)에 맞춰 나이트의 행동 중심과 보스 패턴을 정하고, 이를 RCM 채보로 연결하는 방법을 정리한다. 가사 전문은 저장소에 두지 않고, 연출에 필요한 짧은 구절만 인용한다.

## 1. 전제와 문제

현재 규칙 중 이 설계에 영향을 주는 것:

- 8×8 판. 나이트는 WASD 한 칸 이동, J 공격, K 방어. **공격은 최상단 행(y=7)에서만 피해를 준다.**
- 다음 페이즈 전환 조건은 **보스 HP 0 AND 잡음 수집 목표 달성**이다. 따라서 전환 시점은 플레이 실력에 따라 달라진다.
- 보스 패턴의 간격·예고는 **노트 개수**로 정하고, 패턴 풀은 HP 페이즈(`PhaseMask`)로 고른다. 채보와 연결되어 있지 않다.

이 설계는 보스 패턴이 **곡 구간(싸비 끝)마다 무너지는** 것을 전제로 한다. 그래서 다음 충돌이 생긴다.

| 문제 | 원인 |
|---|---|
| 공격 구간에 나이트가 최상단에 있기 어렵다 | 회피 중심 구간에서 아래로 밀려난 뒤 복귀 비용이 크다 |
| 잡음 수집이 공격 구간을 빼앗는다 | 수집하러 내려가야 하고, 수집이 전환 조건이다 |
| 붕괴 시점이 가사와 어긋난다 | 페이즈는 HP·수집으로 바뀌고, 연출은 곡 구간에 묶여 있다 |
| 예고 시간이 들쭉날쭉하다 | RCM 채보는 노트 간격이 120~3840틱이라 "2노트 예고"의 실제 시간이 크게 다르다 |

해결 원칙: **곡 시계가 패턴 단계·구간 역할·특수 박자를 정하고, 전투 상태는 승패만 정한다.**

## 2. 보스 붕괴 3단계

| 단계 | 구간 | 보스 패턴 성격 |
|---|---|---|
| 1. 정석 | 간주1 ~ 싸비1 | 실제 체스 말의 이동경로 |
| 2. 변형 | 간주2 ~ 싸비2 | 변형 체스(페어리 체스) 말 + 체스에 없는 도형 |
| 3. 붕괴 | Interlude ~ 간주3 | 판 자체가 무너짐 |

단계 전환은 각 싸비 끝의 "판도라를 벨 거야"에서 일어난다(판도라 안의 '판'을 베는 말장난).

## 3. 구간별 설계

| 구간 | 나이트 중심 | 보스 패턴 후보 | 가사 연결 |
|---|---|---|---|
| 간주1 | 회피 | 폰 전진(한 행씩 내려오며 대각선 앞 공격), 단일 룩. 밀도 낮게, 예고 길게 | 튜토리얼 |
| 벌스1 | 회피 + "칵 투" 반격 | 룩 가로·세로, 비숍 대각선, 킹 3×3 주변 덮기, 나이트 L자 8칸 | "각 잡은 악수(惡手)", "손바닥", "훈수" |
| 브릿지1 | 방어 → 회피 → 공격 | 정석 오프닝 순서 고정 → 핀(기존 Lock) → 공격 감소·최상단 비움 | 괄호 응답 "(필요 없어)" = 방어, "(못 박아)" = 핀 회피, "(못 막아)" = 공격 |
| 싸비1 | 전진 → 공격 | 전진 구간에는 공격 없음. 이후 퀸 8방향, 체크(플레이어 행+열, 기존 Cross), 체크메이트 시도 | "거기서 ㅈㅈ 기다려 ㅈㅈ 우리가 ㅈㅈ 어딘가에서 ㅈㅈ"의 2연속 노트 ×4 = 8노트 동안 최상단으로 전진, "나타나 벨 거야"에서 공격 |
| 간주2 | 회피 | 챈슬러(룩+나이트), 아치비숍(비숍+나이트), 첫 비체스 패턴인 판 전체 X자 | 붕괴 쇼케이스 |
| 벌스2 | 방어 + "칵 투" 반격 | 박수 리듬 전체 연타(기존 Chord·Syncopation), 하단·가장자리 뒤치기, 마지막 1노트에 반전하는 예고(반전을 예고에 표시), OMR식 열별 무작위 칸 | "비겁한 박수", "가식", "점수", "답안지" |
| 브릿지2 | 방어 → 회피 → 공격 | 뒤죽박죽 오프닝 + 전체 연타, 좁아지는 고리(우물), 다중 Lock(못 비) | 브릿지1과 같은 가사, 같은 나이트 흐름에 망가진 패턴 |
| 싸비2 | 전진 → 공격 | 전진 구간에는 공격 없음. 이후 가장자리→중앙 수축 충격파(Ring 4단), 판 X자, 판 밖까지 관통하는 퀸 직선 | 싸비1과 같은 전진 구간. 끝에서 2차 붕괴 |
| Interlude | 방어 + 수집 | 킹 3×3 쿵쿵(느리고 무거움), 성검 대베기(판 전체 대각, 방어 필수), 테두리부터 칸 붕괴 | "재위 된 이야기", "필요 없어 성검", "판 밖을 나갈 거야" |
| 싸비3 | 공격 (3연타, 반격) | 체스 잔재와 비체스 패턴 혼합. "둥둥둥" 3노트는 보스 경직 | "시대를 벨 거야". "거기서 기다려" 구절이 없어 전진 구간이 없으므로 "둥둥둥"은 위치와 무관한 반격 박자로 둔다 |
| 간주3 | 공격 마무리 | (a) 1단계 패턴의 역순 재생 후 붕괴, 또는 (b) 보스 전체 3연타 → 방어 → 나이트 3연타 반격 | "(간주 중 3연타)" |

설계 원칙:

- 반복되는 가사(브릿지, 싸비)에서는 **나이트 행동을 같게 두고 보스 패턴만 바꾼다.** 붕괴를 비교로 체감시킨다.
- "칵 투"와 "둥둥둥"은 반복 모티프로 쓰고, 항상 나이트의 공격 박자로 둔다.

## 4. 결정 1: 공격 시 최상단 문제

### 후보와 평가

| 안 | 내용 | 판정 |
|---|---|---|
| A. 최상단 보호 | 공격 중심 구간에서 최상단을 회피 필수로 덮는 패턴(Top Wipe, Upper Crush, Checker) 금지 | 채택 |
| B. 어디서나 공격 | 최상단 규칙 폐지 | 기각 |
| C. 박자 반격 | 특정 박자에 Perfect 방어 시 위치 무관 피해 | 채택 (Perfect만) |
| D. 전진 구간 | 싸비1·2의 "ㅈㅈ" 2연속 노트 ×4(8노트)를 최상단으로 걸어 올라가는 구간으로 쓴다. 새 노트 종류 없음 | 채택 |
| ~~D′. 도약 노트~~ | ~~"나타나"에 입력형 도약 노트~~ | 제거: 채보에 이미 있는 8노트로 충분하고 새 규칙이 필요 없다 |
| E. 공격 구역 확장 | 3단계부터 공격 가능 행 확대 | 선택 (측정 후) |

일곱 관점의 요약:

| 관점 | 핵심 입장 |
|---|---|
| 급진파 | B를 원했으나 위치 선택의 의미가 사라진다. "묶였다가 풀려나는" C+E가 더 급진적이다 |
| 보수파 | A. 기존 HP 보정·경로 검사를 유지하고 싶다 |
| 리듬게이머 | 채보에 이미 있는 2연속 노트가 그대로 이동이 되므로 D를 선호. 박자에 고정된 반격(C)도 선호 |
| 액션게이머 | D는 자동 이동이 아니라 8노트 안에 직접 올라가야 하므로 실력이 반영되어 찬성 |
| 이승윤의 팬 | D는 "거기서 기다려 … 우리가 어딘가에서"에 맞춰 다가가는 연출, C는 "뱉을래 칵 투"를 그대로 연출 |
| 게임 기획자 | "벌스는 아래, 싸비는 위"라는 위치 리듬을 D가 새 규칙 없이 만든다. C의 규칙 추가는 1단계 벌스에서 가르친다 |
| 게임 프로그래머 | D는 새 판정 없이 구간 플래그(공격 공개 금지)만 필요해 가장 저렴. B는 경로 검사·봇·HP 보정을 모두 다시 해야 해 가장 비쌈 |

### 결정

1. 최상단 규칙을 유지한다. 묶인 상태가 있어야 판을 깨는 감각이 생긴다.
2. 싸비1·2의 **"ㅈㅈ" 전진 구간**에서 최상단으로 올라간다. "거기서 ㅈㅈ 기다려 ㅈㅈ 우리가 ㅈㅈ 어딘가에서 ㅈㅈ"의 2연속 노트 4쌍, 총 8노트다.
   - 최하단(y=0)에서 최상단(y=7)까지 7번 이동이면 되므로 8노트면 판 어디서든 도달하고 1노트가 남는다.
   - 전진 구간에는 보스 공격을 공개·발동하지 않는다. 전진 경로를 막지 않기 위해서다. 연출로 "나이트가 떠난 아래 행이 무너지는" 추격을 넣는다면, 1노트에 1행보다 느리게 따라와 최하단에서 출발해도 따라잡히지 않아야 한다.
   - 잡음은 싸비 시작 시 사라지므로 전진 구간에 수집 경로가 끼어들지 않는다.
   - 이미 최상단에 있으면 전진 구간의 노트로 공격할 수 있다.
   - 별도의 도약 노트는 두지 않는다.
3. 공격 중심 구간에서는 최상단을 회피 필수 패턴으로 덮지 않는다. 전진 구간 직후 최상단에 머물 수 있게 한다.
4. "칵 투", "둥둥둥" 박자는 **Perfect 방어 시 반격 피해**를 준다. 위치와 무관하다. 1단계 벌스에서 가르친다.
5. 3단계 공격 구역 확장은 재측정 후 결정한다.

예상 영향: 싸비 공격 구간의 이동은 줄지만 전진 구간이 싸비마다 최대 8번의 이동을 만든다. 공격·이동·방어 3:3:1 목표가 유지되는지 측정한다.

판정창 겹침(코드 확인, 2026-11-12): 전진 구간의 2연속 노트 간격은 120틱(약 172ms)이고 Good 창은 ±140ms라 두 창이 겹친다. 판정 창은 87 BPM의 박 간격(0.69초)으로만 제한되고 노트 간격으로는 줄지 않는다(`RhythmJudge`). 입력은 **가장 가까운 노트**에 배정되고(`AuthoredBeatTimeline.NearestBeat`, 같은 거리면 앞 노트), 이미 쓴 노트면 `BeatAlreadyUsed`로 버려진다(`RhythmSession.RequestAction`). 그래서 실제 창은 앞 노트 [−140, +86]ms, 뒤 노트 [−86, +140]ms로 쪼개진다.

- 앞 노트를 86ms보다 늦게 치면 그 입력이 뒤 노트로 배정되고, 두 번째 입력은 버려지며, 앞 노트는 Miss가 된다. 한 쌍에서 이동 1번을 잃는다.
- 뒤 노트를 86ms보다 일찍 치면 앞 노트로 배정되어 버려지고, 뒤 노트가 Miss가 된다. 역시 이동 1번을 잃는다.
- 봇 시뮬레이션은 노트 시각에 정확히 입력하므로 이 문제를 측정하지 못한다.

입력 오차를 정규분포로 가정한 Python 재현(4쌍 8노트, 10만 회; 사람의 실제 오차 분포는 미측정):

| 입력 오차 | 현재: 8/8 | 현재: 7 이상 | 대안 A: 8/8 | 대안 B: 8/8 |
|---|---:|---:|---:|---:|
| σ40ms, 치우침 없음 | 88.1% | 99.5% | 93.7% | 99.6% |
| σ40ms, 30ms 늦게 | 70.2% | 96.2% | 70.8% | 97.7% |
| σ40ms, 30ms 일찍 | 70.2% | 96.3% | 97.0% | 97.7% |
| σ60ms, 치우침 없음 | 49.1% | 87.3% | 64.5% | 85.2% |

- 대안 A: 가장 가까운 노트가 이미 쓰였으면, 창 안에 있는 다음 미사용 노트로 넘긴다. 이른 입력만 구제한다. 기존 의미 변화가 가장 작다.
- 대안 B: 창 안의 가장 이른 미사용 노트에 배정한다(일반 리듬게임 방식). 늦은 입력도 구제하지만, 일부러 앞 노트를 쉬고 뒤 노트에 행동하려던 입력이 앞 노트로 당겨져 행동 시점이 한 노트 빨라질 수 있다.

1노트 여유는 σ40ms 수준에서는 대부분 흡수하지만(7 이상 96~99%), 오차가 큰 플레이어에게는 부족하다. 판정 규칙 변경은 전진 구간만이 아니라 채보 전체(16분음표 10곳)에 영향을 주므로 별도로 결정한다.

## 5. 결정 2: 잡음 시스템

### 후보와 평가

| 안 | 내용 | 판정 |
|---|---|---|
| A. 현행 유지 | 8박 생성, 수집 AND HP로 전환 | 기각: 싸비 도중 전환되어 가사와 어긋난다 |
| B. 제거 | 이동은 회피 전용 | 기각: 이동 비중과 경로 판단이 사라진다 |
| C. 조율 게이지 | 구간 제한 생성, 수집량 = 판도라 일격 위력, 전환은 곡 시간 고정 | 채택 |
| D. 잔해형 | 보스 공격이 터진 칸에 잡음이 남음 | 3단계 연출로만 고려 |

### 결정

1. 잡음은 간주·벌스·Interlude·브릿지 앞부분에서만 생성한다. 싸비와 "못 막아" 구간에서는 생성하지 않는다. 싸비가 시작될 때 남은 잡음은 사라진다.
2. 수집량은 싸비 끝 **"판도라를 벨 거야" 일격의 위력**이 된다. 하나도 못 모아도 최소 위력은 보장한다.
3. 붕괴 단계 전환은 곡 시간(싸비 끝)에 고정한다.
4. 각 단계의 보스 HP에 **하한**을 둔다. 그 단계의 판도라 일격 전에는 하한 아래로 내려가지 않고, 넘친 공격은 게이지로 들어간다(기존 `HpFloor` 분류를 응용). 공격이 버려지지 않고 클라이맥스도 지켜진다.
5. 곡 끝까지 보스 HP가 남으면 시간 초과, 플레이어 HP 0이면 사망. 기존 종료 규칙은 유지한다.

수집이 전환을 막는 조건에서 빠지므로 현재 미달 항목인 "입력 5% 누락 시 클리어율 73.0%"가 개선될 것으로 예상하지만, 측정 전까지는 예상이다.

## 6. RCM 채보와 보스 패턴 연결

### 현재 채보

`Assets/_Project/Data/Songs/Charts/검을현 채보 v1.json` (formatVersion 1, 480틱/박, 87 BPM).

### 구조: 별도 "보스 채보" 파일

플레이어 채보와 같은 틱 격자를 쓰는 **별도 RCM 파일**(예: `검을현 보스 v1.json`)을 만들고, RCM에서 같은 음원을 들으며 찍는다. 플레이어 채보의 빈 트랙을 쓰지 않는 이유는 나중에 플레이어 레인을 늘릴 때 충돌하기 때문이다.

| 트랙 | 역할 | 찍는 방법 |
|---|---|---|
| Note_1 | 보스 공격 큐 | tap = 그 틱에 발동(예고는 패턴 기본값을 박 단위로 역산). hold = 머리에서 예고 공개, 꼬리에서 발동. 짧은 간격으로 이어진 tap은 한 패턴의 연타(`Hits`)로 묶는다 |
| Note_2 | 구간 경계 | 각 구간 시작에 tap 하나. 순서대로 구간 표와 대응한다. 싸비1·2의 전진 구간은 별도 구간으로 경계를 찍는다 |
| Note_3 | 사용 안 함 | 플레이어 레인과 혼동을 피한다 |
| Note_4 | 특수 노트 표시 | 플레이어 노트와 같은 틱에 찍는다. 의미는 구간이 정한다: 벌스 = 반격, 싸비 끝 = 판도라 일격, 싸비3·간주3 = 3연타. 전진 구간은 Note_4가 아니라 Note_2 구간 경계로 표시한다 |

모든 연결은 **틱 기준**으로 한다. 노트 번호는 채보를 고치면 밀리기 때문이다.

### 구간 표 (ScriptableObject)

Note_2 경계 순서대로 한 행씩 둔다. 현재 `PhaseMask`의 역할을 대신한다.

| 필드 | 의미 |
|---|---|
| Name | 간주1, 벌스1, … |
| Stage | 붕괴 단계 1~3 |
| PatternPool | 큐와 랜덤 채움이 고를 패턴 목록·가중치 |
| NoiseAllowed | 잡음 생성 허용 |
| ProtectTopRow | 최상단 회피 필수 패턴 금지 |
| AdvanceWindow | 전진 구간. 이 구간에 발동하는 큐·랜덤 공격을 금지하고, 예고 공개도 하지 않는다 |
| FillDensity | 랜덤 채움 간격 가중치(0이면 큐만) |
| SpecialMeaning | 이 구간의 Note_4 표시가 뜻하는 것 |

### 실행 규칙

1. **큐 우선.** Note_1 큐의 발동 시각은 바꾸지 않는다. 모양은 그 구간의 패턴 풀에서 고른다.
2. **랜덤 채움.** 기존 `RandomAttackSchedule`을 재사용한다. 큐 사이에서만, 구간 표가 허용할 때만 넣는다. 큐 직전 일정 박 안에는 새 공개를 하지 않는다.
3. **공정성 검사.**
   - 랜덤 공격: 지금처럼 실행 중에 검사하고 연기·생략한다.
   - 큐: 연기하면 싱크가 깨지므로 **가져오기 단계에서 검사**한다. 판의 모든 칸에서 출발해 예고 안에 피하거나 막을 수 있어야 한다. 실패하면 가져오기를 거부하고 작가가 큐를 고친다.
   - 큐 공개 이후의 랜덤 채움은 기존처럼 공개된 큐를 포함해 경로를 검사한다.
4. **예고는 이중 조건.** 필요한 행동 수만큼의 노트와 최소 시간(예: 1박 ≈ 0.69초)을 모두 확보한다. 16분음표가 몰린 구간에서는 새 예고를 공개하지 않는다.

### 고르지 않은 방식

- 완전 랜덤(현재): 가사와 싱크가 맞지 않는다.
- 모든 공격 수작업: 작업량이 크고, 플레이어 위치를 알 수 없어 공정성을 보장하기 어렵다.
- 노트 밀도에서 자동 추출: 밀도로는 어느 박이 어떤 가사인지 알 수 없다.

## 7. 구현 순서

1. `RcmChartImporter`가 보스 파일의 Note_1/2/4를 `SongDefinition`의 새 배열(큐 틱, 큐 hold 끝 틱, 구간 틱, 특수 틱)로 읽는다. 가져오기 단계에서 큐 공정성을 검사한다.
2. 구간 표 에셋을 만들고 패턴 풀 선택을 `PhaseMask`에서 구간 기준으로 바꾼다.
3. `BossPatternSystem`을 큐 우선 + 랜덤 채움으로 바꾼다. 예고 이중 조건을 적용한다.
4. 전진 구간(공격 공개·발동 금지), Perfect 반격, 최상단 보호 규칙을 추가한다.
5. 잡음 생성 구간 제한, 조율 게이지, 판도라 일격, 단계별 HP 하한을 추가한다. 전환 조건을 곡 시간으로 바꾼다.
6. 런타임·설정·로그 버전을 battle-5로 올리고, 리플레이에 새 이벤트(큐 공개·반격·일격)를 포함한다.
7. 321노트 채보 기준으로 `BattleAnalysis`를 다시 실행해 보스 HP, 반격 피해, 일격 최소·최대 위력을 정한다.
