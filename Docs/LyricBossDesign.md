# 가사 연동 보스 설계

2026-11-12 작성. 같은 날 battle-6과 보스 채보 기준으로 갱신했다. **설계 문서이며 구현·측정은 하지 않았다.**

기준 문서: 보스 채보 형식과 검증기는 [BossChart.md](BossChart.md), 채보 밸런스와 빠른 구간 규칙은 [ChartBalance.md](ChartBalance.md), 피날레와 전체 흐름은 [GameFlow.md](GameFlow.md)를 따른다. 보스 채보를 텍스트로 쓰기로 한 결정은 재판 기록 [VERDICT.md](../.court/20261111-020833/VERDICT.md)에 있다. 이 문서의 수치(반격 피해, 보스 HP 등)는 모두 미정이며 재측정으로 정한다.

곡 「검을 현」의 구간(간주·벌스·브릿지·싸비·Interlude)에 맞춰 나이트의 행동 중심과 보스 패턴을 정하고, 이를 보스 채보(`.bosschart.txt`)로 옮기는 방법을 정리한다. 가사 전문은 저장소에 두지 않고, 연출에 필요한 짧은 구절만 인용한다.

## 1. 기준(battle-6)과 남은 문제

이 설계에 영향을 주는 현재 규칙:

- 8×8 판. 나이트는 (3,3)에서 시작해 WASD로 한 칸 이동, J 공격, K 방어. **공격은 최상단 행(y=7)에서만 피해를 준다**(`AttackResolver`).
- 곡은 RCM 채보 `NORMAL1-Note_3`, 321노트(0부터 셈), 87 BPM.
- **빠른 구간 규칙**: 예고 공개 다음 노트부터 마지막 타격까지 사이에 한 박(0.69초)보다 짧은 노트 간격이 있으면 그 공격은 나오지 않는다. 랜덤 모드는 실행 중에 미루고(`BossPatternSystem.CrossesFastSection`), 보스 채보는 검증기가 실패로 처리한다.
- **보스 채보 모드**: 노트 번호·8×8 모양(0/1/2)·경고·연타·`phase>=`·`anchor`로 공격을 직접 적는다. 검증기는 64칸 어디서 출발해도 피할 길이 있는지, 빠른 구간, 안전 칸 보호를 검사한다. battle-7부터 스테이지에 보스 채보가 연결되어 **노트 0–123(가사 1단계)은 채보, 124부터는 랜덤 패턴**이다(`random 124`).
- **피날레**: 보스 HP를 다 깎으면 킹이 무력화되고 패턴이 멈춘다(`Halt`). 곡 끝 16분 3연노트(304~306번, `finishNote` 304)가 시작될 때 무력화 상태면 승리, 아니면 실패다. 무력화 후 남은 판은 바깥부터 무너진다.
- 페이즈 전환은 여전히 **보스 HP 0 AND 잡음 수집 목표**다. 보스 HP는 35/8/14/54. 봇 측정에서 무력화 후 여유 노트 중앙값은 39, 즉 무력화는 보통 265번 노트 부근(Interlude 직후)에 일어난다.

| 처음 제기한 문제 | 상태 |
|---|---|
| 예고 시간이 들쭉날쭉하다 | **main이 해결.** 빠른 구간 규칙으로 한 박보다 짧은 간격을 걸친 공격이 사라졌다 |
| 붕괴 시점이 가사와 어긋난다 | **보스 채보로 해결 가능.** 공격을 노트 번호로 적으므로 단계별 모양을 그 단계의 노트에 두면 된다. HP 페이즈와 무관하다(`phase>=`를 쓰지 않는 한) |
| 공격 구간에 나이트가 최상단에 있기 어렵다 | 남음. 5절 |
| 잡음 수집이 공격 구간을 빼앗는다 | 남음. 6절 |
| 2연속 노트에서 판정창이 겹친다 | 남음. 5절 |
| 노트 번호가 곡 구간과 연결되지 않는다(재판 기록의 지적) | 2절이 채운다 |

해결 원칙: **곡 시계가 패턴 단계·구간 역할·특수 박자를 정하고, 전투 상태는 승패만 정한다.** 보스 채보가 이 원칙의 앞부분을 이미 만족한다.

### 보스 채보에 넣을 `section` 초안

`section`은 검증 보고서의 이름표일 뿐 게임 동작에 영향이 없다. 이름에는 공백을 쓸 수 없고, 범위가 겹치면 앞 줄이 우선한다. 1단계는 확정(간주1 32노트, 벌스1 30노트, 브릿지1 28노트, 싸비1 34노트, 홀드는 1노트)이고, 2단계부터는 청음으로 범위를 정한 뒤 추가한다.

```
section 간주1 0-31
section 벌스1 32-61
section 브릿지1 62-89
section 싸비1-전진 90-97
section 싸비1 98-123
section 싸비2-전진 200-207
section 피날레-3연타 304-306
```

## 3. 보스 붕괴 3단계

| 단계 | 구간 | 보스 패턴 성격 |
|---|---|---|
| 1. 정석 | 간주1 ~ 싸비1 | 실제 체스 말의 이동경로 |
| 2. 변형 | 간주2 ~ 싸비2 | 변형 체스(페어리 체스) 말 + 체스에 없는 도형 |
| 3. 붕괴 | Interlude ~ 간주3 | 판 자체가 무너짐 |

단계 전환은 각 싸비 끝의 "판도라를 벨 거야"에서 일어난다(판도라 안의 '판'을 베는 말장난). 보스 채보에서는 단계마다 다른 모양을 그 단계의 노트 범위에 적는 것으로 구현한다.

3단계의 "판이 무너진다"는 battle-6 피날레의 "무력화 후 판이 바깥부터 무너진다"와 연출이 같다. 무력화가 Interlude 부근에서 일어나는 현재 밸런스에서는 Interlude의 "판 밖을 나갈 거야"와 맞지만, 싸비3의 보스 패턴은 대부분 나오지 않는다(6절의 결정 필요 항목).

설계 원칙:

- 반복되는 가사(브릿지, 싸비)에서는 **나이트 행동을 같게 두고 보스 패턴만 바꾼다.** 붕괴를 비교로 체감시킨다.
- "칵 투"는 반복 모티프로 쓰고 나이트의 공격 박자로 둔다. 곡 끝 3연타는 battle-6 피날레가 이미 승리 박자로 쓴다.

### 보스 채보로 그리는 법

| 패턴 | 보스 채보 표현 | 비고 |
|---|---|---|
| 룩 가로·세로, 체크 | `anchor` 십자 모양 | 시작용 채보의 `십자`와 같은 방식 |
| 비숍 대각선 | `anchor` X 모양 | 판 전체 X자는 `anchor` 없는 고정 X |
| 퀸 8방향 | `anchor` 십자 + X | |
| 킹 3×3, 나이트 L자 8칸 | `anchor` 모양 | 판 밖으로 나간 칸은 잘린다 |
| 핀 | 가운데 한 칸만 그린 `anchor` 모양 | 여러 칸 핀은 고정 산포로 그린다 |

| 수축 고리, 체커 반전 | 고리·체커마다 별도 모양을 이어지는 노트에 | 안전 칸 보호 검사에 걸리는지 검증기로 확인 |
| 가식(예고 반전) | 두 모양을 같은 노트에 동시 표시 | 공개 후 범위를 바꾸지 않는 규칙 때문에 "마지막 1노트에 반전"은 제외. 같은 노트에 두 공격은 검증기 경고 대상 |
| OMR식 무작위 칸 | 고정 산포를 손으로 그림 | 보스 채보는 매 판 같다 |

### 결정

1. 최상단 규칙을 유지한다. 묶인 상태가 있어야 판을 깨는 감각이 생긴다.
2. 싸비1·2의 **"ㅈㅈ" 전진 구간**(90–97, 200–207)에서 최상단으로 올라간다.
   - 최하단(y=0)에서 최상단(y=7)까지 7번 이동이면 되므로 8노트면 판 어디서든 도달하고 1노트가 남는다.
   - **빠른 구간 규칙이 공격 금지를 이미 보장한다.** 91–98번이 빠른 간격이라 이 노트들에 타격하거나 이 노트들을 걸쳐 예고하는 공격은 나오지 않는다. 별도 구간 플래그(이전 안의 `AdvanceWindow`)는 필요 없다.
   - 예외: 전진 구간의 첫 노트(90, 200)는 앞 간격이 한 박이라 그 노트에 타격하는 공격은 허용된다. 거기서 방어하면 이동이 정확히 7번 남아 여유가 없다. **보스 채보 작성 규칙으로 90·200번 타격을 피한다.** 검증기 경고로 만들지는 선택이다.
   - 전진 구간 연출로 "나이트가 떠난 아래 행이 무너지는" 추격을 넣는다면, 1노트에 1행보다 느리게 따라와 최하단에서 출발해도 따라잡히지 않아야 한다.
   - 이미 최상단에 있으면 전진 구간의 노트로 공격할 수 있다.
3. 공격 중심 구간에서는 최상단을 회피 필수 칸(`2`)으로 덮지 않는다. 보스 채보 작성 규칙으로 두고, 구간 이름과 연결한 검증기 경고는 선택 제안이다.
4. "칵 투" 박자는 **Perfect 방어 시 반격 피해**를 준다. 위치와 무관하다. 1단계 벌스에서 가르친다. 신규 메커니즘이며 보스 채보에 박자를 표시할 방법이 필요하다(7절).
5. 3단계 공격 구역 확장은 재측정 후 결정한다.

예상 영향: 싸비 공격 구간의 이동은 줄지만 전진 구간이 싸비마다 최대 8번의 이동을 만든다. battle-6의 행동 비율(42.3/45.5/12.2)이 목표 43/43/14 ±4 안에 남는지 측정한다.

### 판정창 겹침 (코드 확인)

전진 구간의 2연속 노트 간격은 120틱(약 172ms)이고 Good 창은 ±140ms라 두 창이 겹친다. 판정 창은 87 BPM의 박 간격(0.69초)으로만 제한되고 노트 간격으로는 줄지 않는다(`RhythmJudge`). 입력은 **가장 가까운 노트**에 배정되고(`AuthoredBeatTimeline.NearestBeat`, 같은 거리면 앞 노트), 이미 쓴 노트면 `BeatAlreadyUsed`로 버려진다(`RhythmSession.RequestAction`). 그래서 실제 창은 앞 노트 [−140, +86]ms, 뒤 노트 [−86, +140]ms로 쪼개진다. 세 파일 모두 battle-6에서 바뀌지 않았다.

- 앞 노트를 86ms보다 늦게 치면 그 입력이 뒤 노트로 배정되고, 두 번째 입력은 버려지며, 앞 노트는 Miss가 된다. 한 쌍에서 이동 1번을 잃는다.
- 뒤 노트를 86ms보다 일찍 치면 앞 노트로 배정되어 버려지고, 뒤 노트가 Miss가 된다. 역시 이동 1번을 잃는다.
- 봇 시뮬레이션은 노트 시각에 정확히 입력하므로 이 문제를 측정하지 못한다.

입력 오차를 정규분포로 가정한 Python 재현(4쌍 8노트, 10만 회; 사람의 실제 오차 분포는 미측정):

| 입력 오차 | 현재: 8/8 | 현재: 7 이상 | 대안 A: 8/8 | 대안 B: 8/8 |
|---|---:|---:|---:|---:|
| σ40ms, 치우침 없음 | 88.1% | 99.5% | 93.7% | 99.6% |
| σ40ms, 30ms 늦게 | 70.2% | 96.2% | 70.8% | 97.7% |
| σ40ms, 30ms 일찍 | 70.2% | 96.3% | 97.0% | 97.7% |
| σ60ms, 치우침 없음 | 49.1% | 87.3% | 64.5% | 85.2% |

- 대안 A: 가장 가까운 노트가 이미 쓰였으면, 창 안에 있는 다음 미사용 노트로 넘긴다. 이른 입력만 구제한다. 기존 의미 변화가 가장 작다.
- 대안 B: 창 안의 가장 이른 미사용 노트에 배정한다(일반 리듬게임 방식). 늦은 입력도 구제하지만, 일부러 앞 노트를 쉬고 뒤 노트에 행동하려던 입력이 앞 노트로 당겨져 행동 시점이 한 노트 빨라질 수 있다.

1노트 여유는 σ40ms 수준에서는 대부분 흡수하지만(7 이상 96~99%), 오차가 큰 플레이어에게는 부족하다. 창이 겹치는 120틱 간격은 채보에 10곳(91·93·95·97, 201·203·205·207, 305·306)이고, 305·306은 승리 확정 뒤라 판정이 없다. 실제 영향 범위는 두 전진 구간이다.

## 6. 결정 2: 잡음 시스템

### 후보와 평가

| 안 | 내용 | 판정 |
|---|---|---|
| A. 현행 유지 | 8박 생성, 수집 AND HP로 전환 | 기각: 싸비 도중 전환되어 가사와 어긋난다 |
| B. 제거 | 이동은 회피 전용 | 기각: 이동 비중과 경로 판단이 사라진다 |
| C. 조율 게이지 | 구간 제한 생성, 수집량 = 판도라 일격 위력, 전환은 곡 시간 고정 | 채택 (battle-6과 대조 필요, 아래) |
| D. 잔해형 | 보스 공격이 터진 칸에 잡음이 남음 | 3단계 연출로만 고려 |

### 결정 (battle-6 이전에 내린 것)

1. 잡음은 간주·벌스·Interlude·브릿지 앞부분에서만 생성한다. 싸비와 "못 막아" 구간에서는 생성하지 않는다. 싸비가 시작될 때 남은 잡음은 사라진다.
2. 수집량은 싸비 끝 **"판도라를 벨 거야" 일격의 위력**이 된다. 하나도 못 모아도 최소 위력은 보장한다.
3. 붕괴 단계 전환은 곡 시간(싸비 끝)에 고정한다.
4. 각 단계의 보스 HP에 **하한**을 둔다. 그 단계의 판도라 일격 전에는 하한 아래로 내려가지 않고, 넘친 공격은 게이지로 들어간다(기존 `HpFloor` 분류를 응용).
5. 곡 끝까지 보스 HP가 남으면 실패, 플레이어 HP 0이면 사망.

### battle-6과의 관계

| 항목 | battle-6 현재 | 관계 |
|---|---|---|
| 1. 싸비에 잡음 생성 금지 | 8박 격자로 곡 전체에 생성 | **충돌 없음.** 그대로 추가할 수 있다 |
| 2. 판도라 일격 | 없음 | 신규. 위치(싸비1·2 끝 노트)부터 청음으로 확정해야 한다 |
| 3. 단계 전환을 곡 시간에 고정 | 패턴 단계는 보스 채보 모드면 이미 곡 시간 기준. 페이즈는 HP+수집 기준 | **패턴 쪽은 해결.** 남는 것은 HP 페이즈와 보스 HP 막대를 곡 시간에 맞출지 여부 |
| 4. 단계별 HP 하한 | HP 0 → 무력화 → 304번 결정 노트 | **결정 필요.** 하한을 두면 무력화가 싸비3 이후로 밀려 지금의 "무력화 후 39노트 여유"가 사라진다. 대신 싸비3 패턴이 나오게 된다 |
| 5. 실패 조건 | 304번까지 무력화 못 하면 실패 | battle-6 규칙으로 대체한다 |

결정이 필요한 질문: **보스를 싸비3 전에 무력화할 수 있게 둘 것인가(battle-6 그대로), 아니면 단계별 HP 하한으로 무력화를 싸비3 이후로 묶을 것인가.** 앞쪽은 Interlude의 "판 밖을 나갈 거야"와 판 붕괴 연출이 맞고, 뒤쪽은 싸비3 "시대를 벨 거야"의 보스 패턴이 살아난다. 결정 전까지 2·4번은 보류하고 1번만 진행할 수 있다.

## 7. 보스 채보로 연결

이전 판의 "RCM 별도 파일의 Note_1/2/4 트랙으로 보스 큐를 찍는" 안은 **텍스트 보스 채보로 대체되었다.** 옛 안의 요소가 main에서 무엇에 해당하는지:

| 옛 안 | main의 대응 |
|---|---|
| Note_1 보스 공격 큐(tap = 발동, hold = 예고 구간) | 공격 줄 `노트 모양 경고 [hits every]` |
| Note_2 구간 경계 + 구간 표 | `section 이름 시작-끝`(이름표만). 구간별 패턴 풀은 모양을 해당 노트에 적는 것으로 대신한다 |
| 큐 공정성을 가져오기 단계에서 검사 | 검증기의 64칸 출발 회피·안전 칸 보호 검사. 실패는 노트 번호와 함께 보고된다 |
| 예고 이중 조건(노트 수 + 최소 시간) | 빠른 구간 규칙 |
| 랜덤 채움 | `random N` 지시어: 채보가 끝나면 노트 N부터 랜덤 패턴이 이어받는다. 둘은 겹치지 않는다 |
| `AdvanceWindow` | 빠른 구간 규칙으로 대체(5절) |
| Note_4 특수 노트(반격, 판도라 일격) | **대응 없음.** 새 지시어가 필요하다. 제안: `mark 반격 <노트>`, `mark 판도라 <노트>`. 검증기는 표시된 노트가 범위 안인지, 빠른 구간과 겹치는지 검사한다 |
