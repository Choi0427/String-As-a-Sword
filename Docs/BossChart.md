# 보스 채보

보스의 공격을 곡의 노트 번호에 맞춰 텍스트 파일 하나에 직접 적는 방식이에요. 채보를 연결하면 랜덤 패턴(`Patterns`, `Attack Schedule`) 대신 채보대로 공격해요. 매 판 같은 노트에 같은 공격이 나와요. `random` 줄을 쓰면 채보가 끝난 뒤부터 랜덤 패턴이 이어받아요.

- 채보 파일: `Assets/_Project/Data/Bosses/GeomEulHyeon.bosschart.txt` (battle-8: 곡 끝까지 채보만 써요. 아래 "싸비 기준 3단계" 참고)
- 코드: `Scripts/Combat/BossChart.cs`(파서), `BossPatternSystem`의 채보 모드, `Editor/BossChartValidator.cs`(검증기)

## 쓰는 법

`#` 뒤는 주석이에요. 빈 줄은 무시해요.

### 구간

```
section 후렴 97-140
```

검증 보고서에 `노트 120 [후렴]`처럼 이름이 붙어요. 게임 동작에는 영향이 없어요.

### 모양

```
shape X
20000002
02000020
00100100
00011000
00011000
00100100
02000020
20000002
```

- 8줄 × 8칸이고, 첫 줄이 판의 맨 윗줄(플레이어가 시작하는 줄)이에요.
- `0` = 공격 없음, `1` = 일반 공격(가드하거나 피함), `2` = 강공격(가드하면 가드가 깨지고 맞아요. 피해야 해요).
- 판 전체가 `1`이면 피할 칸이 없으니 **가드 전용** 공격이에요. 판 전체가 `2`면 막을 수도 피할 수도 없어서 오류예요.
- `shape 십자 anchor=4,4`처럼 `anchor=줄,칸`(1부터 셈)을 붙이면, 공격을 보여주는 순간 그 칸이 플레이어 위치에 오도록 모양이 옮겨져요. 판 밖으로 나간 칸은 잘려요.
- 공격마다 소환되는 체스 기물은 모양을 보고 **자동으로** 정해져요. 아래 [기물 규칙](#기물-규칙)을 보세요. 모양을 새로 그리거나 고치면 기물도 따라 바뀌어요.

### 공격

```
# 노트  모양  경고  [hits=연타수 every=간격]  [phase>=페이즈]  [piece=기물]
120     X     3
130     X     3     hits=4 every=2
200     X     2                       phase>=3
210     X     2                                    piece=폰
```

| 항목 | 뜻 | 범위 |
|---|---|---|
| 노트 | 첫 타격이 떨어지는 노트 번호 (0부터) | 곡 노트 수 미만 |
| 경고 | 몇 노트 전에 보여줄지. `노트 - 경고`가 닫히는 순간 보여줘요 | 1~5 |
| hits, every | 같은 모양을 `every` 노트 간격으로 `hits`번 연타 | 1~8, 1~4 |
| phase>=N | 보여주는 순간 보스 페이즈가 N 이상일 때만 공격하고, 아니면 건너뛰어요 | 1~4 |
| piece=기물 | 이 공격만 자동 규칙 대신 이 기물을 소환해요. [직접 바꾸기](#직접-바꾸기) 참고 | 폰 룩 비숍 나이트 킹 퀸 없음 |

- 페이즈가 바뀌어도 이미 보여준 공격은 취소되지 않아요. 피날레에서 보스가 스턴되면 모두 사라져요.
- 모양은 파일 어디에 정의해도 돼요. 공격 줄보다 아래에 있어도 괜찮아요.

### 랜덤으로 넘기기

```
random 124
```

- 노트 124부터 스테이지의 랜덤 패턴(`Patterns`, `Attack Schedule`)이 이어받아요. 채보의 모든 공격이 발동한 뒤에 넘어가요. 랜덤 공격의 첫 타격은 124 이후예요.
- 채보와 랜덤은 동시에 떠 있지 않아요. 그래서 채보 타격이 이 노트 이상이면 검증기가 실패로 처리해요.
- 넘어간 뒤에는 랜덤 모드와 똑같이 동작해요. 인게임 페이즈의 `PhaseMask`를 따르고, 페이즈가 바뀌면 예고를 취소해요.
- `random` 줄이 없으면 곡 끝까지 채보만 써요. battle-8의 `GeomEulHyeon.bosschart.txt`는 `random` 줄을 쓰지 않아요.

## 예고 표시 (숫자)

공격받는 **모든 칸의 정중앙**에 그 칸이 몇 노트 뒤에 맞는지 숫자로 보여 줘요(2026-11-29).

- 경고 1노트 공격도 `1`을 보여 줘요. 공격마다 다르던 규칙(경고 2 이상만, 16칸 넘으면 2×2마다 하나)은 없앴어요.
- 숫자는 검은색, 글꼴은 Chakra Petch(`ArtSet.outcomeFont`), 굵게예요. 배지 배경이나 색 구분은 없어요.
- 한 칸에 공격이 겹치면 가장 먼저 떨어지는 공격의 남은 노트예요.
- 일반(`1`)과 강공격(`2`)은 장판 무늬로 구분해요(강공격은 빗금).
- 코드: `PrototypeView`(숫자, `DangerFontSize`), `TelegraphHud.MapCells`(칸별 남은 노트).

## 기물 규칙

공격이 터지는 순간 보스가 체스 기물을 소환해서 장판을 **휩쓸거나**(기물이 길을 따라 달려감) **내려찍어요**(기물이 한 점에 쿵). 연출만 바뀌고 판정은 그대로예요. 타격 칸에는 따로 표시(X 장판)가 없어요.

- 기물은 타격 0.45초 전에 나타나요. 휩쓰는 기물은 시작 칸에서 판 위로 솟아오르고(살짝 튀어나왔다 자리 잡음), 찍는 기물은 위에서 내려와 목표 칸 위 공중에 멈춰요(살짝 내려갔다 자리 잡음).
- 타격 0.2초 전에 힘을 모아요. 휩쓰는 기물은 뒤로 당기며 몸을 젖히고, 찍는 기물은 위로 올라가요.
- 찍는 기물은 마지막 0.07초에 가속하며 내리꽂혀 타격 순간에 착지하고, 짧게 튀었다가 흔들리며 자리 잡아요. 휩쓰는 기물은 타격 순간 튀어나가 점점 느려지고, 앞으로 기울었다 바로 서며, 끝에서 살짝 지나쳤다 돌아와요.
- 타격 순간 화면이 흔들려요(퀸 7, 킹 5, 폰·나이트 3, 휩쓸기 2픽셀). 0.3초 머문 뒤 판 아래로 가라앉아요.
- 찍는 기물이 공중에 있는 동안 바로 아래 칸에 둥근 그림자가 생겨요. 기물이 내려올수록 진하고 작아지고, 착지하면 사라져요.
- 기물은 반투명(불투명도 0.75, `BossPieceArtSetup.Opacity`. 1 = 불투명, 0 = 안 보임)이라 뒤의 경고 장판과 기사가 비쳐 보여요.
- 기물은 크기나 모양이 변하지 않고 위치만 움직여요. 시간은 곡 시간에 맞춰요. 값은 `BoardWorldPresenter`의 `LeadSeconds`, `EnterSeconds`, `WindUpSeconds`, `DropSeconds`, `HoldSeconds`, `SinkSeconds`, `HoverHeight`, `WindUpHeight`, `PullBack`, `Bounce`, `Overrun`, `SweepSeconds`예요.

어떤 기물이 어떻게 움직일지는 모양(`1`과 `2` 칸, 둘 다 같게 봐요)을 보고 자동으로 정해요(2026-11-28 결정). 위에서부터 차례로 보고, 처음 맞는 규칙을 써요.

### 직접 바꾸기

자동 결과가 마음에 들지 않으면 `piece=`로 바꿔요. 예: "#20은 비숍 말고 폰으로" → 보고서에서 #20의 줄 번호를 찾아 그 공격 줄 끝에 `piece=폰`을 붙여요.

```
73   오프닝3-Bc5 1   piece=폰     # 이 공격만
shape 핀강 anchor=5,4 piece=킹    # 이 모양을 쓰는 모든 공격
```

- 공격 줄의 `piece=`가 모양 줄의 `piece=`보다 우선해요.
- `폰` `나이트`: 공격 칸마다 하나씩 내려찍어요.
- `퀸`: 장판 가운데에 하나가 내려찍어요.
- `룩` `비숍` `킹`: 자동 규칙이 정한 움직임(휩쓰는 길, 찍는 자리)은 그대로 두고 기물만 바꿔요.
- `없음`: 기물을 소환하지 않아요.
- 기물은 하나만 쓸 수 있어요. `룩+나이트` 같은 조합은 자동 규칙(2번)이 정해요.

### 기물 모델

`Art/Models/BossPieces/`의 Meshy 모델이에요(보스 가면 톤의 단색 회색, 반투명, 실제 체스 기물 높이 비율 K 97 · Q 89 · B 79 · N 72 · R 66 · P 55mm, 보스 나이트 = 플레이어 나이트 높이). **String As a Sword → Art → Set Up Boss Chess Pieces**가 프리팹을 만들고 `ArtSet`의 `Boss Pawn`~`Boss Queen` 칸에 넣어요. 전체 크기는 `Boss Piece Scale`로 조절해요. 칸이 비면 코드로 그린 실루엣이 나와요.

## 싸비 기준 3단계 (battle-8)

2026-11-12 회의에서 싸비를 기준으로 보스 패턴을 세 단계로 나누기로 했어요. `GeomEulHyeon.bosschart.txt`가 이 순서로 적혀 있어요.

| 단계 | 구간 | 노트 | 패턴 | 공격 수 |
|---|---|---|---|---:|
| 1 | 간주1 ~ 싸비1 | 0-123 | 기본 체스 기물의 공격 경로 (폰·룩·비숍·나이트·킹) | 29 |
| 2 | 간주2 ~ 싸비2 | 124-233 | 페어리 체스 기물 (챈슬러, 아치비숍, 아마존, 나이트라이더, 카멜+지브라, 알필+다바바, 베롤리나 폰) | 30 |
| 3 | Interlude ~ 싸비3 | 234-303 | 체스 규칙으로는 말이 안 되는 모양 (회의록 예시의 이중고리, 창살, 나선, 반쪽, 외길 등) | 21 |

- 단계는 **곡의 노트 번호**로 정해져요. 보스 HP 칸(화면의 PHASE 1~4)과는 따로 움직여요. HP 페이즈를 곡 시간에 맞출지는 아직 정하지 않았어요([LyricBossDesign.md](LyricBossDesign.md) 6절).
- 회의록의 "싸비 N 전"을 "싸비 N이 끝나기 전까지"로 읽었어요. 싸비가 시작할 때 단계를 바꾸려면 싸비 구간의 공격 줄만 다음 단계 모양으로 바꾸면 돼요.
- 2·3단계의 구간 경계(간주2 124-141, 벌스2 142-171, 브릿지2 172-199, 싸비2 208-233, Interlude 234-263, 싸비3 264-303)는 1단계 구간 길이에 맞춘 추정이에요. 청음으로 확인이 필요해요.
- 싸비2 전진 구간(200-207)과 그 앞 197-199는 비워 두었어요. 싸비 구간에서는 최상단 줄 전체를 `2`로 덮지 않아요.
- 보스는 보통 265번 노트 부근에서 스턴되므로 싸비3의 공격은 대부분 나오지 않아요.

## 스테이지에 연결

`Assets/_Project/Data/Stages/FourPhasePrototype.asset`의 **Boss Chart** 칸에 채보 파일을 끌어다 놓아요. 비우면 다시 랜덤 패턴으로 돌아가요. 규칙이 바뀌는 것이므로 연결할 때 `Combat Version`을 올려 주세요. 현재 `GeomEulHyeon.bosschart.txt`가 연결되어 있고 `battle-8`이에요.

## 검증

Unity 메뉴 **String As a Sword → Boss Chart**에서 실행해요.

- **Validate**: 채보를 검사해요. Project 창에서 `.bosschart.txt`를 선택했으면 그 파일을, 아니면 기본 채보를 검사해요.
- **Validate and Simulate (200 seeds)**: 검사를 통과하면 이어서 봇 시뮬레이션을 돌려요. 클리어율, 공격·이동·방어 비율, 남은 노트를 기존 기준과 함께 보여줘요. 몇 분 걸려요.

결과는 `Docs/BossChart/validation.txt`에 저장돼요(시뮬레이션은 `Docs/BossChart/sim/`).

### 실패로 보는 것

| 검사 | 기준 |
|---|---|
| 범위 | 경고가 곡 시작 전에 시작하거나, 마지막 타격이 곡 노트 수를 넘음 |
| 빠른 구간 | 경고부터 마지막 타격까지 사이에 한 박(0.69초)보다 짧은 노트 간격이 있음 |
| 피할 길 | 판 **64칸 어디에서 출발해도** 경고 안에 피할 수 있어야 해요. 일반(`1`) 칸도 랜덤 패턴과 같이 피할 길이 있어야 하고, 가드 전용 공격만 이 검사를 건너뛰어요. 연타는 앞 타격과 그때 떠 있는 다른 공격까지 피하는 길로 검사해요 |
| 안전 칸 보호 | 먼저 보여준 공격이 끝나기 전(또는 같은 노트)에, 그 공격이 안전하다고 보여준 칸을 새 공격이 때림 |

### 경고만 하는 것

- 피날레 노트 이후의 공격: 보스가 스턴되면 나오지 않아요.
- 같은 노트에 공격 두 개.

보고서의 칸 표기 `(줄,칸)`은 그림과 같은 기준이에요. 위에서 몇 번째 줄, 왼쪽에서 몇 번째 칸이에요.

### 근사인 부분

`anchor` 모양이 다른 공격과 동시에 떠 있으면, 다른 공격의 위치를 같은 출발 칸 기준으로 계산해요. 실제로는 그 공격을 보여줄 때 플레이어가 다른 곳에 있었을 수 있어요. 이런 겹침은 봇 시뮬레이션으로 한 번 더 확인해 주세요.

## 배치 모드

```
Unity.exe -batchmode -quit -projectPath <프로젝트> -executeMethod StringAsASword.Editor.BossChartValidator.RunFromCommandLine [-bossChart 경로] [-bossChartSeeds 200] [-bossChartOutput Docs/BossChart]
```

채보가 실패하면 종료 코드 1로 끝나요. 에디터가 열려 있으면 배치 모드가 같은 프로젝트를 열 수 없어요.
